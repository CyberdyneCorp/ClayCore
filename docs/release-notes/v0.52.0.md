# claycore v0.52.0

Three minor versions in one tag. v0.49.0 made a **session** survivable — one undo
across every representation, a journal that outlives a crash, a bounded history,
a way out of a four-second call. v0.52.0 is the release that makes the engine
**reachable and affordable**: three capabilities that existed in C++ and could be
used from no host at all are now reachable from both bindings, ClayCore and
CyberRemesherAndUV finally share a file format, and a brush dab stopped costing
what the whole model costs.

**23 merged PRs, 42 commits, 19 OpenSpec changes folded into the living specs.
The C ABI gained 30 entry points with nothing removed, no signature changed and
no struct re-laid out.**

Verified on this tree: `ctest` 5/5, **1,445 unit test cases / 13.2M assertions**,
**511 pyclay tests** (1 skipped), `openspec validate --all --strict` clean, and a
full 61-case run on the reference iPad — valid, clean tree, nominal thermals at
both ends, no case over budget.

Every bump in this range is additive and a host compiled against 0.49.0 keeps
linking. **Four existing entry points now return something different**, each
because the old answer was wrong — see [What moves under
you](#what-moves-under-you) before re-recording goldens.

## The theme: a dab costs what it touches

Nine changes, one program, one sentence: **nothing left in a brush dab scales
with the size of the model.** Every one of them was found by profiling rather
than predicted, and every one is byte-identical to the code it replaced or says
plainly where it is not.

Measured on a 12-core Mac, Release, unless a row says otherwise.

| What was paid for | Before | After | |
|---|---:|---:|---|
| Lipschitz measured over the dense lattice (#270) | 53.60 ms | 4.53 ms | 11.8x at cell 0.01 |
| A document bake walking the tape per point (#271) | 386 ms | 23.6 ms | 16.4x |
| A topological move sampling per point (#275) | 4,605 ms | 305 ms | 15.1x at 193 nodes |
| A relax dab sweeping the whole volume (#272) | 16.7 ms | 2.23 ms | 7.5x, five-cell brush |
| A band shrink re-deriving unchanged bounds (#278) | 2.32 ms | 1.77 ms | steady dab in a stroke |
| A whole-volume snapshot per relax pass (#278) | 1.81 ms | 1.60 ms | steady dab |
| Work done on samples the brush cannot reach (#287) | 1.61 ms | 1.00 ms | 1.61x; 2.71x at cell 0.02 |
| The bake running the whole tape at every sample (#277) | 22.3 ms | 15.2 ms | 193 items, C ABI |
| A flatten dab resampling the whole volume (#300) | 1,800 ms | 28.7 ms | 63x at cell 0.01 |

### The measurements that decided the design

- **`measure_sample_lipschitz` was 31–42% of every bake** and asked `sample_at()`
  for 8.1M points of a bounding lattice storing 1.55M samples in 2,132 of 15,625
  brick slots. Six million of those returned nothing. Walking the stored bricks
  instead takes the phase to **3%** of the bake. The two traversals see the same
  pairs — a forward pair lies wholly inside one brick — and a test keeps the
  dense walk as an independent oracle and requires **exact equality**.
- **A tape instruction costs ~10 ns and its arithmetic costs 1 ns**, so the
  interpreter is most of a bake and the interpreter was per point. The three
  document-sourced C entry points and their pyclay equivalents now fill a pooled
  block. Byte-identity is the contract rather than a tolerance, and
  `check_bench.py` gates the pooled form against the serial one so the two cannot
  silently diverge again.
- **A brush is a ball and the bricks selected for it are a box.** At cell 0.02
  with radius 0.05, 64 bricks are selected and 17 are reachable — **95% of the
  samples were wasted.** The region narrows to the ball, the base value comes
  from the brick being written rather than a lookup, and the falloff compares
  squared distances.
- **Culling the bake's tape is not always worth it, and the blend decides.** A
  600-dab sphere compiles to 1,199 instructions and any one brick needs 5.4 — but
  a smooth union's cull pad grows with `k`: 3.4x at `k=0`, 2.2x at `k=0.04`, 1.5x
  at `k=0.06`, and **0.80x — a loss — at `k=0.10`.** So the fill probes a sample
  of the lattice and falls back above a third of the document's tape. The probe
  samples the **whole** lattice and not the first window, because a window is a
  slab at the bottom of the region where every tape culls to nothing, and probing
  it chose culling for documents that then ran 1.7x slower.
- **Removing a 9% copy bought 11%.** The per-pass whole-volume snapshot became a
  snapshot of the region about to be rewritten, and the win is larger than the
  copy it removed because a brush's worth of bricks stays in cache where a stencil
  tap against the whole volume runs a sparse index into six megabytes. Written the
  obvious way the replacement was **correct and 4% slower**; it needed the
  single-brick fast path in front of the eight-way search.

### On device, on the release gate itself

The tag's own run: **61 cases on the reference iPad (iPad15,5, iPadOS 26.5.2),
valid, clean tree, `thermalState` nominal at both ends, no case over budget.**
p95 at the top of each axis, against the same cases measured on the v0.49.0-era
run of the identical harness:

| Case | v0.49.0 | v0.52.0 | |
|---|---:|---:|---|
| `sdf_flatten` | 6.677 ms | **0.654 ms** | 10.2x |
| `sdf_relax` | 1.661 ms | **0.719 ms** | 2.31x |
| `volume_hpolish` | 149.673 ms | **5.261 ms** | 28x — but see below |
| `sdf_consolidate` | 340.462 ms | 326.147 ms | 1.04x |
| `mask_extrude` | 4,442.964 ms | 4,387.581 ms | 1.01x |
| `sdf_move` | 0.0893 ms | 0.0889 ms | flat, and see the canary below |

**`volume_hpolish` is a gallery case and its number is indicative, not a
measurement.** The gallery bundle times each stroke of a progressive sculpt once,
and a stroke cannot be repeated without changing the sculpt it builds. It is
quoted because it is the only device case that reaches the flatten path and
because the Mac A/B predicts a change of that size (40.8 → 0.765 ms for a
five-cell dab). The `devicemeasure` rows above it reproduce to under 0.5%.

`sdf_relax`'s device fixture is a 0.05-cell volume at `region_radius` 0.4, which
is the **least** favourable case for a brush that now follows its own footprint —
the same dab is 3.9x at a 0.02 cell on a Mac. 2.31x is the floor of that range.

**Two cases were measured hot, and both are faster anyway.** The run-level canary
reads x1.79 (130.38 ms at 1 s against 233.79 ms at 136 s) with `thermalState`
`nominal` at both ends, which is the case that check exists for. Per-case, only
`sdf_flatten` (x1.50) and `sdf_relax` (x1.42) sit past tolerance — they are at the
end of their bundle and pay for everything ahead of them — so the two largest wins
in the table were taken on a throttled tablet and are conservative.

**The thermal window closed because the program succeeded**, and that is stated
rather than hidden. `mask_extrude` runs first and takes ~116 s either way. Then
relax and flatten went from 52 s and 53 s to 6 s and 7 s once they were pooled
across every core: 105 seconds of single-threaded work left the device at x1.07,
and 13 seconds of pooled work takes it to x1.50. **A benchmark suite whose pacing
depends on how long its own fixtures take to build stops being comparable the
moment the fixtures get faster**, and this program made them 28x faster. That is
what the per-case canary bracket in [Gates](#gates-that-were-reporting-something-other-than-what-they-checked)
exists to survive; re-ordering cannot restore the cold window, because the heat
sources are themselves budgeted cases.

## An appended dab stops re-uploading the document (#197)

A sculpt grows a node per brush stamp, and a host that raycasts to place the next
dab reads the whole-document tape, cached on the document revision and thrown away
by every edit. **At 50,000 items that re-emitted 99,999 instructions and 7.8 MiB
so that ~148 bytes could go on the end** — and then re-uploaded all 7.8 MiB to the
GPU, because the reused tape has different bytes and so a fresh `compile_id`, which
is what a backend keys residency on.

Both halves are closed.

- **Compile (phase 1).** The compiler already emits items left to right and never
  moves what it has written, so the prefix needs no relocation pass — only an
  invalidation that knows an append happened, which `AddNodeCmd{parent = kNoNode,
  index = -1}` already says. **0.544 ms against 10.3 ms at 50,000 items, 18.9x**
  (28.8x at 1,000; the ratio is bounded by `memcpy`, since reuse trades an O(N)
  compile for an O(N) copy). `compile_document_append` verifies the caller's claim
  itself and refuses rather than trusting it.
  **Layers are the subtlety**: they do not concatenate — each visible SDF layer is
  folded into the ones below by a hard union emitted *after* its chain — so the
  checkpoint is a truncation point and the union is re-emitted after the append.
  Emitting an appended item after the union is invisible for a hard `Add`, because
  `min` is associative, and the **wrong field** for a smooth blend or a subtract.
- **Upload (phase 2), Vulkan.** A tape now names the tape it grew from and the
  offset in each section where the two stop agreeing. On an RTX 5060, 300 dabs on
  a 20,000-item document: **0.333 ms of host CPU per dab against 9.44 ms, and 0
  buffer reallocations against 300.** It also retires Vulkan's `memcmp` and the
  full 7.8 MiB CPU-side shadow of the tape it compared against.
- **Upload (phase 2), Metal.** The deferred half, landed with the three things the
  Vulkan work learned the hard way: patch on `parent_id`, advance the resident
  entry's id or only the first dab of a stroke patches, and reserve slack at
  `newBuffer` time because an `MTL::Buffer` cannot be resized. Mac: **2.02 ms of
  host CPU per dab against 2.70, 0 reallocations against 300.** On the reference
  iPad, per dab across the growth axis, `sdf_stroke_metal` reads
  **0.236 / 0.374 / 1.806 ms** against `sdf_stamp_metal`'s 0.401 / 0.983 / 1.867 —
  the same dab with and without an invalidation between dabs.

Metal holds four tapes resident under an LRU, so the entry a patch belongs in is
found by ancestor id while the entry an upload evicts is found by least-recent
use: **patch into the wrong slot and a pick tape silently becomes the stroke.**
Tested, and the tests were mutation-checked — a wrong patch offset, a resident id
left unadvanced, and slack removed each fail them.

**The device harness had no case that reached the append path at all.** Every
latency case resets between iterations and the reset *is* the invalidation, so the
suite was blind to this by construction. `sdf_stroke_metal` times a whole stroke
and divides, because there is no reset that restores a document without breaking
the chain under test.

## Surface groups, reachable (ABI 0.50.0, `.clayspace` minor 13)

`add-surface-groups` shipped a `GroupField` that could **say** a surface point was
hidden and nothing that **asked**. It was reachable from no host — no C entry
point, no pyclay, no serialisation — and hiding a group hid nothing, because the
mesher never asked. 11 of 25 tasks were done and the row was reported landed.

This is the other 14: grow / shrink / border, a `'GRUP'` chunk, undo, 21 C entry
points (19 `clay_groups_*` plus two on the document), pyclay, an example and the
docs. **Hiding now hides.**

- **A triangle filter, not a change to the field.** Making hidden regions evaluate
  as empty is the obvious implementation and is wrong twice: it changes what the
  *document means*, and it carves a boundary into the surface, so the mesher closes
  the hole with new geometry and showing the group again would not restore the
  original triangles. Filtering the produced mesh is exactly reversible, and a test
  asserts the count returns to the byte.
- **Quad-aware by construction.** `mesh_data.h` makes it a rule that rewriting
  `indices` clears `quads`, so a triangle-wise filter would hand back a quad export
  carrying no quads.
- **Skipping a hidden hit took three attempts.** Advancing past the hit by an
  epsilon leaves the ray *inside* the shape, where the field is negative and a
  sphere-march cannot step. Walking forward until the field goes positive
  overshoots by construction, because that point *is* the far wall. What is wanted
  is the next sign change whose point is visible.
- **The render caught what the tests did not.** The example's first run produced
  byte-identical images for "whole" and "isolated": two of four picking paths were
  unwired with every test green.

Honest limits, recorded in the header, the ABI, the docs and the example: the
boundary is quantised to the lattice rather than the representation, and grow is
**volumetric, not geodesic**, so a fold closer than `steps` cells is crossed rather
than followed. What does *not* respect the hidden set — eval, brushes, save, the
exporters — is listed rather than left to be discovered.

**Format note.** Minor 13 adds a new chunk, so it is the mild kind: an older build
skips it and opens the document with no groups. The one-directional loss is worth
naming — such a build **saving the document back drops every group and every
hidden flag**, so a region an artist had put away comes back visible. That is the
safe direction: geometry reappearing is obvious and recoverable, geometry silently
staying hidden is neither.

## Field queries for a baker (ABI 0.51.0)

The same gap as surface groups, found the same way: `brush::mask_from_surface` had
three files, tests, and no C entry point, no pyclay, no change folder. A sweep of
every public header against both bindings confirms it was the last one.

The measure moves to `brush/surface_measure.h` and the mask becomes one of its
callers, so there is **one stencil** — which makes "a cavity mask and a baked map
agree about this surface" a construction instead of a claim.

- **Ambient occlusion and thickness**, which `procedural_mask.h` had deferred
  explicitly as a different cost class. Occlusion is *occlusion*: 0 is open sky.
- **Bounded rays** (`clay_raycast_bounded`), because `clay_raycast` searches to
  infinity — "look 5 mm along this normal" could not be said, and a miss was
  indistinguishable from a hit on the far side of the model, which is what puts
  garbage in bake seams.
- **Cage projection** (`clay_project_to_surface`, `_many`), which took three
  implementations. A plain sphere-march cannot start *inside* the surface, and
  marching `|f|` fixes the stepping and breaks the stopping. What works: step by
  `|f|`, detect the crossing by **sign change** between consecutive samples,
  bisect. Unambiguous from either side.
- **Determinism is not negotiable**, and a hemisphere sample was the first thing in
  the tree that could quietly break it. The pattern is a Hammersley sequence
  XOR-scrambled by a hash of the **quantised** point and an explicit seed —
  quantised so two points a float-epsilon apart get the same rotation rather than
  two unrelated ones, which would read as film grain across neighbouring texels.
  Tested for bit-identity *and* that a different seed differs, or the first check
  would be vacuous.

Still open and recorded as such: `ray_count` / `ray_length` defaults are unmeasured,
cross-backend determinism is untested (the walk is CPU-only today), and the bake
example needs a UV layout.

**A C++ source break for embedders**, and the point of the change rather than a
side effect: `SurfaceMeasure` moved header, and `ProceduralMaskSettings`'s measure
fields (`scale`, `direction`, `threshold`) moved into a nested `measure` member
shared with the per-point form. No C or Python caller is affected — neither could
reach the feature at all before this release.

## The sculpt handoff (ABI 0.52.0)

`CyberRemesherAndUV/docs/sculpt-handoff-format.md` defines a sculpt handoff, ships
the **reading** half only, and records that agreement with ClayCore was outstanding
because no negotiation ever took place. Their CLI already assumed our half existed:
`producer --for-retopo | cyberremesh --target -`.

**Two hazards their reader enforces that we would have violated**, neither findable
from this side: `save_ply` declares a mesh's **quads** as its faces when it has
them and their reader rejects any other arity — so our *best* export was exactly
the file it would refuse — and normals are required, while a mesh meshed without
gradients has none. Both are now guarantees of the writer rather than requirements
on the caller.

**Verified against their actual CLI**, not against our own parser:

| Input | Result |
|---|---|
| ClayCore sphere, 11,160 tris | accepted, retopologized to 1,268 quads |
| ClayCore quad export, 1,830 quads | accepted, `droppedFaces` 0, 708 quads out |
| the same mesh via ordinary `save()` | **rejected**, "not a sculpt handoff" |

`material_mix` comes from a **mask**. Their spec calls it a blend weight between
two material slots; ClayCore has none and does not invent them, and a mask is
already a painted scalar in [0,1] answerable at any point. No mask writes zeros.

And **the bake seam turns out to be half-built on their side**, found by reading
their own tasks: a `FieldEvaluator` interface, a `CyberFieldEvaluator` of three C
callbacks, `cyber_bake_field`, a Python base — and no volumetric engine to plug in.
The 0.51.0 queries fill those callbacks with nothing further needed. The
correspondence is documented **with its two traps**: their `occlusion` is *openness*
(1 = open) and ours is occlusion (1 = enclosed), so passing ours straight through
bakes an inverted AO map that looks plausible and is wrong everywhere; and
`CLAY_MEASURE_CURVATURE` is a saturated [0,1] masking value while theirs is signed
mean curvature in 1/length.

The handoff's own version is **1.0 and is not ours**. Their versioning policy
governs it, so `CLAY_HANDOFF_VERSION_*` move only when their spec does.

## Gates that were reporting something other than what they checked

Four of them, and the pattern is the same each time: a check that cannot fail reads
exactly like a check that passed.

- **The bindings row had been green on a fallback since before v0.49.0.**
  `check_binding_parity.py` compares the parsed `pyclay_module.cpp` against
  **itself** when no module can be imported, and `release_check.py` never built
  pyclay. A row reading "the bindings match the ABI" was checking that the source
  matches itself. The checklist now configures with `-DCLAY_BUILD_PYTHON=ON` and
  passes `--pyclay <build>/bindings/python --require-import`, and `--pyclay` is
  **authoritative** — no other build tree, virtualenv or installed wheel may answer
  for it, because that is how the same gate went false-*red* on v0.49.0 against a
  stale module a different tree happened to hold. Three regression tests, run in a
  subprocess on purpose, plus a control case so the two failure cases are not
  satisfied by a gate that fails on everything.
- **The device gate demanded a ten-minute hardware run for a `.py` file.** It
  decides relevance by prefix and `bindings/` is in the list, but the harness is
  Swift against the xcframework and never imports pyclay. The carve-out is
  `bindings/python/tests/` and nothing else; `pyclay_module.cpp` stays in
  deliberately. *A gate that is cheap to satisfy for changes that cannot affect it
  stays trusted; one that is not is a gate people route around.*
- **The canary said a run had drifted and not which cases were measured while it
  had.** v0.49.0's two runs both reported `CONDITIONS CHANGED x1.59` and both had
  **54 of 59 cases measured inside tolerance** — the five that were not sit at the
  end of the measure bundle and pay for everything ahead of them. Cases are stamped
  with their bundle now (`startedAtMs` is a within-bundle offset and a run spans
  three processes), and the settled baseline is the median of the first 10 s rather
  than the lowest sample.
- **A budgeted case is now divided by the machine it ran on.** The gate reported
  `sdf_move` as a 1.6x regression on code that measures 1.05x off-device: it runs
  at 135 s between canary samples at 122 s and 147 s, so the factor it was charged
  with was interpolated **across the thermal transition itself** — the verdict
  depended on where a 30-second timer happened to fire. Each budgeted case now
  records the canary immediately before and after itself and the gate divides by
  the mean of the two. Nothing is interpolated. ~16 s of overhead on a run already
  taking ~250 s.

The re-derived baseline is the first bracketed run: **36 of 61 cases bracketed, 86
canary samples against 15**, valid, nominal at both ends. `sdf_move` normalises to
**0.0791 ms against the cold run's 0.079 — 1.00x**, on the verb the gate had called
a 1.6x regression. And it passes because it is normalised, not because the budget
grew: **the budgets tightened.** `sdf_move` 0.1279 → 0.1187 ms, `sdf_relax` 2.5288
→ 0.8220, `sdf_consolidate` 991.5380 → 373.7525 — the last of which had been
budgeted against a measurement that stopped being true several changes ago and
would have passed a 3x regression.

The bracket earned itself on that first run: `sdf_move`'s two readings are 159.0 ms
before and 135.6 ms after — the case starts hot behind `sdf_flatten` and cools
during itself, so either end alone is wrong in a different direction.

**Why the thermal window closed.** `mask_extrude` runs first and takes ~116 s in
both runs. Then relax and flatten went from 52 s and 53 s to 6 s and 7 s when this
program pooled them across every core: 105 seconds of single-threaded work left the
device at x1.07, and 13 seconds of pooled work takes it to x1.50. The cold window
has been consumed by the program's own success, and re-ordering cannot restore it
because the heat sources are themselves budgeted cases.

## What moves under you

Additive in ABI, but four existing entry points return something other than what
0.49.0 returned. Every one because the old answer was wrong.

- **`clay_brick_cache_mesh` / `_lod` close pinholes.** A cell is owned by the brick
  its low corner falls in and takes its other seven corners from up to seven
  neighbours, so marching the cells that *surface* bricks own is not marching every
  cell that crosses. A brick with no lattice still owns cells that cross whenever a
  neighbour holds a sample of the opposite sign — which takes a field steeper than
  its band across one voxel step, which no true distance field is and **a worked
  document routinely is** (relief and incise displace the surface by an amplitude
  over a region narrower than the amplitude). Measured on the reported shape, a ball
  with forty relief dabs: **28 open boundary edges at voxel 0.05 and 386 at 0.02,
  against 0 for `clay_document_mesh` of the same document** (#292). For a field the
  band brackets there are no such cells and the mesh is unchanged.
- **`clay_item_volume_flatten` stopped inflating the volume it flattens.** It read
  its source back through `eval()`, which outside the band reports the far bound — a
  value that steps by brick rather than by cell — and re-recorded those steps as
  samples. A re-baked ball came back with **1,246 stored bricks declaring a
  Lipschitz of 14 where its source declared 1**, with no flatten applied at all,
  compounding on every stroke. It is **444 bricks at 1.74** now, and 444 at 2.42
  after eight dabs. A host that sized a buffer from the old count sees a smaller one,
  and `safe_step_scale` improves.
- **`clay_item_volume_flatten` with settings that describe no flatten** hands back
  the source volume rather than a resampled copy of it. That branch means "the
  source, unchanged", and the volume *is* the source.
- **Culled evaluation is now bit-identical to the full tape inside the region it
  promised that for.** For a hard union it always was; for a smooth union it was
  not, and the gap is not rounding. 95 of 1,627 in-band samples differed on a
  600-node document at `k=0.06`, and **0.0091 — half a cell — at 25 nodes** (#282).
  The mechanism is the chain: an item's influence bound is dilated by what *one*
  blend can move, but the accumulated value part way down a long chain sits well
  above where it ends up, so an item whose final contribution is nothing can still
  steer the running value. The compiler now pads by the largest single-item reach in
  the layer, exactly as it already padded for a feathered replace. **The spec says
  plainly that this term is not a bound** — the drag grows with chain length — since
  a spec implying a proof here would claim something measured to be false.

Nothing here is a compatibility break. They are listed because a host with golden
images or pinned brick counts will see them and should re-record rather than go
looking for a regression.

## Fixes

- **A flatten dab lost 8% to argument evaluation order** (#290). Factoring the
  per-sample blend into a shared `flatten_at` made the call
  `flatten_at(settings, pl, p, source(p))` — and `source(p)` is an *argument*, so it
  is evaluated before the body. `source` is a `std::function`, which the optimiser
  must treat as able to touch anything, so every read of `settings` inside
  `flatten_at` now happened after an opaque call and was reloaded. `flatten_at`
  takes the source as a **callable** now, which keeps the one shared implementation
  and restores the ordering: weight first, source second. 4.31 → 4.00 ms.
  *Passing the `Plane` by value was tried first, on the theory that the reference
  was the cost. It made no difference, and that is recorded so nobody spends the
  same hour.*
- **A `ProgressScope` misuse MSVC caught and GCC did not.** The second argument is
  a phase count and the work count was passed: it narrows `size_t` to `uint32_t`,
  which MSVC `/WX` rejects and GCC accepts silently, and it means the wrong thing.
  Same class as the `extern "C"` linkage break in #235 — a warning only one of the
  three CI compilers raises, so a green local build proves nothing.
- **UBSan caught a `memcmp` of two null pointers at zero length.** A document of
  plain prims compiles to no blob at all, and an empty vector's `data()` is null.
  The three tape compares moved behind a helper that returns early on empty.
- **An example wrote to a relative path.** `63_surface_groups` saved to
  `output/63_groups.clayspace`, which only resolves when the cwd happens to be
  `examples/`. Every other example that writes a file uses `R.output_path`. Verified
  by running from the repo root, which is what CI does, rather than by rerunning the
  way that worked.
- **A cross-representation test was vacuous.** It asserted `g.at(p) ==
  g.get(g.cell_at(p))` — the inline *definition* of `at()`, an identity that holds
  however wrong the field is — and ran 1,700 assertions comparing the mechanism to
  itself. Replaced with a sphere both meshed and rasterized, membership compared at
  corresponding points of two genuinely different samplings.
- **`openspec/config.yaml` is tracked**, so the schema new changes are scaffolded
  with is pinned rather than implicit.
- **The roadmap and docs were re-derived against what shipped.** The roadmap header
  read v0.30.0 against a tree at 0.52.0, five landed rows were shown pending, and
  two completed changes had no entry. `docs/sculpt_comparison.md` said the pipeline
  seam had not started and neither engine owned it — **wrong in both directions**
  once someone read the other repository. `docs/07` still said a host wanting undo
  over voxel edits was snapshotting them itself, which has been false since
  `unify-the-undo-history`.

## Known limits, stated rather than discovered

- **The whole-surface meshing path got slower, and that is the fix.** Collecting the
  straddling cells takes it 171 → 190 ms on a forty-dab relief ball; the 128-key
  frame path goes **7.9 → 5.9 ms**, because `shell_cells` now walks owner bricks
  rather than each key's ring and needs no hash set and no sort (42 → 14 ms on
  6,003 bricks). Closing the surface costs what it costs.
- **The bake's tape cull is refused for wide blends.** Above a third of the
  document's tape the fill runs whole, because culling is a loss at `k=0.10`. The
  guard measures rather than assumes, and `BM_VolumeBakeCulledDoc` against
  `BM_VolumeBakeWholeTapeDoc` is gated as a ratio so a guard that quietly decides
  never to cull fails.
- **`clay_item_volume_flatten_from` deliberately does not cull.** Flatten draws the
  samples onto a plane *after* the fill produces them, so a brick the fill saw as
  empty comes back holding the surface and stores values that were never refined.
  The precondition is on `document_block_fill` itself.
- **A flatten dab still has two terms that scale with the model**: the compact
  rebuild and the far-bounds chamfer. At cell 0.01 with eight balls, 11.2 ms of the
  28.7 is the volume copy the overload returns. Both were already the accepted trade
  and are ~60x cheaper per brick than the evaluation they replaced.
- **`move_topological`'s geodesic walk is left sequential on purpose.** It is 4–5%
  of the operation and makes 87k of its 2.09M source calls; the sampling pass is
  where the time was.
- **Gallery cases are not bracketed by the canary.** They set no per-case context
  and keep the raw comparison. The `devicemeasure` bundle is the trustworthy half
  and reproduces to under 0.5% across runs; the gallery cases time each stroke of a
  progressive sculpt once, and a stroke cannot be repeated without changing the
  sculpt it builds. **Read the per-case record, not the run-level flag.**
- **`sdf_stamp_cpu` remains outside the engine's half of a 120 Hz frame.** Its budget
  is a regression ceiling, not an endorsement, and the checker reprints the breach
  on every run so writing it down does not retire it.
- **`sdf_stamp_*` budgets still carry more headroom than they were set with**,
  because the corrected stamp spread is faster than the sheet the fixture used to
  lay down. Unchanged from v0.49.0.
- **Cross-backend determinism of the surface measures is untested**; the hemisphere
  walk is CPU-only today.
- **The xcframework's Metal slice remains unverified on real hardware** by this
  repository. The build fails rather than shipping a CPU-only slice and the Swift
  smoke asserts the backend registers, but "`clay_list_backends` reports metal on a
  real iPad" has not been observed here.

## Upgrading

1. **Nothing in this range breaks source or ABI compatibility for a C or Python
   caller.** A host compiled against 0.49.0 keeps linking.
2. **C++ embedders**: `SurfaceMeasure` moved to `brush/surface_measure.h`, and
   `ProceduralMaskSettings`'s `scale` / `direction` / `threshold` are now inside a
   nested `measure` member. One include and one member path.
3. **If you pin brick counts, golden meshes or declared Lipschitz values,
   re-record them.** See [What moves under you](#what-moves-under-you) — the new
   numbers are the correct ones.
4. **If you save a `.clayspace` with an older build, it drops every surface group
   and every hidden flag.** Documents are backward-open at minor 13; a round trip
   through an old writer is lossy in that one direction.
5. **If you consume the sculpt handoff**, note that `CLAY_HANDOFF_VERSION_*` tracks
   CyberRemesherAndUV's spec rather than this library's version, and that their
   `occlusion` is the inverse of `CLAY_MEASURE_OCCLUSION`.
6. `CMakeLists.txt`, `bindings/c/clay.h` and `pyproject.toml` all declare **0.52.0**.
