# claycore v0.84.0

Six minor versions in one tag: 0.79.0 through 0.84.0. The theme of v0.78.0 was
that **a surface is something a tablet can hold**. This one is narrower and
older: **the engine stops paying for what it provably cannot reach.**

Almost everything here is one argument applied in a different place. A brick
that is uniform is not walked. A grab whose ball a brick cannot touch is not
compiled into that brick's tape. A sampled volume is cropped to the region
reading it. A layer moved rigidly is not re-evaluated at all, because its
surface afterwards **is** its surface before, moved. A cold brick starts from a
resident prefix instead of the whole history. And an intersect's layer extent —
which v0.78.0 made finite and, without meaning to, made quadratic — is computed
once a frame instead of once per query.

The one genuinely new capability is the other side of the same coin: **a
captured region of the field is now an asset**. Sculpt a detail once, name it,
place it a thousand times, and every placement shares one payload in memory and
on disk.

**18 merged PRs, 47 commits on main, 17 OpenSpec changes. The C ABI gained 31
entry points with nothing removed, no existing signature changed and no struct
re-laid out.** The scene and `.clayspace` formats go to **minor 17**.

Four issues close: **#306** (a cold brick pays for the whole history),
**#451** (an intersect drag got 1.17x dearer at v0.78.0), **#452** (a Move grab
permanently taxes every later evaluation) and **#455** (a sampled volume is
compiled whole into every brick that touches it).

## A captured region of the field is an asset (ABI 0.83.0, #463, #453, #450)

An artist could sculpt a shape and not reuse it. Most of what that needs was
already in the tree and this release should not read as though it were not:
`PrimType::Volume` is a sampled field that compiles through the tape, and
`clay_item_volume_from_document` already captured a banded, redistanced region.
Two things were missing.

**An oriented capture.** The existing capture takes a world-axis-aligned box. A
detail sitting on a curved surface has to be captured *about that surface* — +Z
outward, the tangent plane turned by the stylus azimuth — or the asset only
works at the orientation it happened to be taken at.
`clay_stamp_frame_from_surface` builds that frame from a hit, a normal and an
azimuth **through the same `kernel::calpha_frame` the scalar alpha uses**,
fallback included, so a stamp and an alpha placed at one hit cannot disagree
about which way is up. `clay_item_stamp_from_document` captures in it, and the
item that comes back carries the frame as its transform — so a placement is an
ordinary editable, undoable, instanced item and not a new kind of thing.

**The frame is never inferred from the content**, and the header says why: an
orientation derived from the samples moves when the region moves, so
re-capturing the same detail would give an asset that disagrees with placements
already made from it.

**An identity.** `clay_item_stamp_content_id` names an asset,
`clay_item_stamp_save_memory` / `_load_memory` keep one outside a document, and
`clay_document_stamp_memory` counts payloads by pointer identity — so a host can
tell "sixteen placements of one asset" from "sixteen assets" rather than
inferring it from a byte count.

`clay_layer_place_stamps` turns a resolved stroke (`clay_stroke_resolve`'s
output — spacing, pressure, jitter, taper and azimuth already applied) into
placements as **one undo step and one invalidation**, as every other stroke in
this ABI is. Pressure rides into the radius and the radius becomes a uniform
scale against the asset's own natural radius. `strength` maps to **nothing**,
deliberately: multiplying the captured distance by it would scale the *metric*
rather than the sculpt — the zero set moves and the gradient stops having unit
length, which is a field that lies about its own distance.

| gate | measured |
|---|---|
| a capture placed back against its source | **0.000206** over 334 in-band samples, 0.012 cell |
| a hard-squashed placement's safe step | **3,990 steps, 0 crossings** |
| 16 placements of one capture | **1 asset**, one payload |
| a 24-dab resolved stroke | **1 undo step** |
| capture 128³ / one more placement | 179 ms / **0.004 ms** on a 2.95 MB payload |

**And the sharing now survives a save** (#453, format minor 17). `types.h` has
said of both `volume` and `gate` that "several items gated by one painted mask
should not each carry a copy of it", and that was true of memory and false of
the file: every node serialized its own payload, so eight placements of one
capture wrote eight copies and loaded as eight unrelated volumes. Measured,
**8 placements went from 1,499,457 bytes to 189,117** — each extra placement now
costs about 198 bytes, which is the node record. Both halves had to land
together: a writer that deduplicates met by a reader calling `make_shared` per
node has saved disk and rebuilt the duplication in memory, and the next save
writes N payloads again.

Two things this got right the hard way. The payload id is **document-wide and
not a `NodeId`** — node ids are per-layer, every layer numbering from 1, so a
back-reference by node id would name a different node in another layer. And the
frame **round-trips as a quaternion, not as a normal and a tangent**: storing
the two vectors and re-resolving them on load runs the frame back through
`calpha_frame` and a basis-to-quaternion conversion, and that rounds. Before it
changed, every sample of a reloaded stamp differed from the original in the last
ulp — caught because the round-trip gate asserts *field equality* rather than
that the file loaded.

## A layer drag costs one refill, not sixty (ABI 0.82.0, #462)

Moving or rotating a whole layer — the Move/Rotate/Scale gizmo on an object —
changes no shape. Layers combine by hard union, and a layer's transform enters
the compiled tape only as a rigid matrix composed into each item's inverse. So
for a transform that is rigid, or rigid plus a uniform scale, the layer's
surface afterwards **is** its surface beforehand, moved by the same matrix.

The engine did not know that. Every frame of a gizmo drag set the transform,
invalidated the layer's whole box and re-walked every brick in it:

| per drag frame, 5,832 bricks at 0.05 voxel | 100 items | 1000 items |
|---|---:|---:|
| the edit alone | 0.031 ms | 0.133 ms |
| layer translate + display | 12.4 ms | **95.7 ms** |
| `clay_mesh_transform` of the finished 120k-vertex surface | 0.32 ms | **0.30 ms** |

The engine spent 95.7 ms producing what 0.30 ms of matrix multiply already had —
23x over the 4.17 ms interactive frame share at 1,000 items.

**The placement gesture.** `clay_layer_placement_begin` / `_update` / `_preview`
/ `_commit` / `_cancel`. The document does not move until the commit, so sixty
frames record **one** command, take **one** invalidation and undo in **one**
step.

| | refills over a 60-frame drag |
|---|---:|
| `BM_LayerDragPerFrame` | 60 |
| `BM_LayerDragOneRefill` | **1** |

Gated on the **count**, not the clock: the undo depth is asserted on every frame
of the unit test, and `check_bench.py` carries the time ratio beside it only to
catch the categorical failure of a gesture that invalidated per frame anyway.
Every other edit is refused while a gesture is open — the gesture holds no
snapshot of the document, so an edit made underneath it is one it cannot
reconcile, and refusing is the only answer that cannot be quietly wrong.

**The split a preview is drawn from.** `clay_brick_cache_eval_requests_layer`
and `clay_document_mesh_sdf_layer` evaluate the dragged layer alone; the
existing `_excluding` forms evaluate everything else. Their hard union is
**bitwise** the whole document, gated on a three-layer document. The host draws
the two and moves one under the gesture matrix. What a preview drawn that way
does *not* show is the mutual occlusion of the union where the two overlap,
which resolves on commit — stated rather than discovered.

**`clay_layer_placement_report`** classifies a proposed placement as RIGID,
SIMILARITY or GENERAL and hands back the matrix from the old placement to the
new. It is a *query* that changes nothing, which keeps the four existing setters
untouched and makes "asking costs nothing" true by construction.

**Invalidation is unchanged for a host that does not use the gesture.** The
engine still drops what it dropped before, so nothing can go stale on a host
that ignores all of this.

**What measuring the plan refuted.** The design said a uniform layer scale keeps
"a rounded or blended shape similar to itself". Half of that is true:
`n->rounding * placed_distance_scale(...)` scales and `emit_combine` pushes
`blend.k` as it stands. Two boxes blended at k=0.12 and scaled by 2 measured a
field ratio of **1.289** where a similarity says 2. Fixing that would change what
every existing document with a scaled, blended layer evaluates to — a decision
with a format and a gallery behind it. So it is left alone and the
classification is made honest instead: such a scale reports GENERAL and promises
nothing.

## A cold brick starts from a prefix (ABI 0.79.0 and 0.84.0, #449, #464)

The resumable refill made a dab *inside* a stroke flat in document size. What
was left was the brick that has never been filled — and a stroke crosses brick
planes constantly, so that is a hitch in the middle of a gesture rather than a
one-off:

| items | first touch of a window | the same window warm |
|---:|---:|---:|
| 5,000 | 3.2 ms | 0.004 ms |
| 20,000 | 12.9 ms | 0.006 ms |
| 50,000 | **37.8 ms** | 0.004 ms |

`SdfPrefixCache` — a coarse resident volume over the head of a layer's history —
already was the fix, and had been since ABI 0.79.0. **It was reachable only from
the Smooth transaction.** 0.79.0 (#449) put it across the ABI:
`clay_sdf_prefix_cache` as a host-owned handle (it takes no document, and
destroy returns void, because "a cache belongs to whoever made it, never to a
document" is what `clay_brick_cache` already says), `_build`, `_build_for_refill`,
`_invalidate_layer`, `_clear`, `_set_max_bytes`, `_stats`,
`clay_sdf_prefix_boundary_for`, and `clay_sdf_smooth_begin_cached`.
`clay_sculpt_policy` grew the three cache knobs — appended behind the
`struct_size` it already negotiates, and **all three zero is today's behaviour
exactly**, so a host that has not heard of this is not opted into it.

0.84.0 (#464) pointed it at the refill.
`clay_brick_cache_eval_requests_seeded` seeds a brick with no seed at all from
the layer's cached prefix and evaluates only the roots after the boundary,
storing the result as an ordinary seed so the second touch takes the existing
warm path:

| items | unseeded | seeded |
|---:|---:|---:|
| 5,000 | 1.69 ms | **0.271 ms** |
| 20,000 | 7.68 ms | **0.290 ms** |
| 50,000 | 14.65 ms | **0.291 ms** |

**Flat** — 0.271 to 0.291 ms across a ten-fold document, and 50x at 50,000
items. Exact to 4.5e-07 over 26,245 in-band samples, with 94–95 of 96 bricks
served by the prefix. Held by a benchmark that compares the same window on two
documents of different size rather than against the unseeded row, because
*flatness* is the claim and a ratio cannot make it. **This closes #306.**

**A seed is only exact on the lattice it was built for.** Smooth's working field
is the layer's padded region; a refill's lattice is the brick grid anchored at
the world origin. Read across the two, a seed is an interpolation of two samples
rather than one of them — 0.011 at a 0.05 cell, a quarter of a cell, against
3.1e-07 aligned. Snapping unconditionally was tried and is wrong: it moves
Smooth's prefix off Smooth's lattice. So alignment is a **policy choice and part
of the cache key**, and the two consumers hold separate entries.

**And the residual was not where it was guessed, twice.** Phase timers put 3.5 ms
of a 5.4 ms window in the *suffix compile*: `compile_layer_suffix` given a cull
region but no index re-derives the document's cull pad by walking every layer's
items, **per brick**. The cold path had been written to skip taking the cull
index on the reasoning that `plan_frontier` does not need one. It does not; the
per-brick suffix compile underneath it does. Taking it took that phase from
**3,500 µs to 24 µs**.

## What a grab costs after it lands (ABI 0.80.0, #457, #465 — issue #452)

`clay_layer_move_surface` reads like a bounded local edit. It is not: each grab
is recorded as a **warp** on every item it reached, and a warp is evaluated per
sample for as long as it is in the edit list. Re-baselined across every
host-facing path:

| grabs | warps | eval_points | gradients | raycast | mesh | brick refill | safe step |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 0 | 0.29 ms | 1.24 | 10.2 ms | 35.3 ms | 0.0019 ms | 1.00000 |
| 12 | 248 | 1.34 | 6.6 | 81.5 ms | 172 ms | 0.0013 ms | 0.10322 |
| 50 | 1,673 | 6.48 | 32.0 | **1000 ms** | **1792 ms** | **0.0008 ms** | **0.00008** |

**The issue's headline is real and its diagnosis was incomplete.** Composing two
warps into one is a research question, not a fix, and this release does not
pretend otherwise. Three things that *are* soundly available landed instead.

**A culled tape drops a warp it cannot reach** (#457). Sound by induction along
the chain: deformers warp in authoring order, so if every warp so far has been
the identity over the region, the point is where it started and the next may be
tested against the same region; a warp that is kept may move the point, so the
region is dilated by the most that warp can move it before the next test.
Measured on a brick-sized region:

| a brick-sized region | tape params | 512-probe eval |
|---|---:|---:|
| far from every grab | 32 (no warps) | **0.0052 ms** |
| under the grabs | 176 (all twelve) | 0.0824 ms |

**This helps the per-brick paths only** — a refill, and meshing with gradient
normals. A whole-document evaluation has no region to test against and pays for
every warp, so the `eval_points` column above is unchanged by it. Said plainly
rather than left for someone to discover.

**`clay_layer_warp_cost`** reports what the layer is currently carrying — items,
warped items, warps, and what an evaluation is being charged for them.
`clay_layer_consolidation_cost` already answered what *baking* would cost; a
host's first question is whether the layer has accumulated enough to be worth
baking, and there was no way to ask.

**And the chain's declared Lipschitz was wrong in two ways** (#465), which is
where the 79x raycast and 44x mesh actually came from — the safe step scale
collapsing to 8e-05 makes the marcher take ~12,500x more steps, and that is not
a per-warp cost at all.

- *The travel budget between two links is the travel between them*, not the whole
  chain's. Summing every link's travel means each new grab widens the budget
  every other pair is measured against: fifty drags of 0.05 gave a budget of 2.5
  against balls of radius 0.3, so every pair on a form 1.7 across counted as able
  to meet.
- *Each link is priced against its own neighbourhood, not its connected
  component.* The old grouping was a union-find over "these two can meet", and
  that relation is transitive where "both act at one point" is not: balls A–B and
  B–C may overlap with A and C disjoint, and no point sees all three. A stroke
  chained every drag into one group and charged the product of the lot. Still an
  upper bound, and the argument is short: every link acting at one point contains
  that point, so they pairwise can meet, so they all lie inside any one of their
  neighbourhoods.

| sixteen grabs along a bar, each overlapping only its neighbours | safe step scale |
|---|---:|
| 2 grabs | 0.748 |
| 16 grabs, before | **0.098** |
| 16 grabs, after | **0.647** |

**6.6x.** On the issue's own fixture at 12 grabs: step 0.103 → 0.469, and a
raycast 81.5 → 51.6 ms.

## An intersect's bound stopped being quadratic (ABI 0.81.0, #454, #459, #461 — issue #451)

v0.78.0 shipped a real improvement: an edit to a `CLAY_OP_INTERSECT` item
invalidates its layer's box rather than the whole brick cache. Issue #451
reported the bill for it — a live boolean drag costing **1.17x** more on v0.78.0
than v0.73.0, with a subtracting control on the identical fixture completely
flat.

The reporter's own hypothesis was wrong, and so was the first fix. What
regressed is not the refill; it is the **bound query**. An intersect's influence
bound *is* its layer's extent, and taking that extent walks every visible node
computing its geometry bound — which for a stroke or a sweep re-tessellates its
curve, for a mirrored item bounds every copy, and for a deformer chain runs its
slope probes. Before v0.78.0 an intersect answered "everything" in constant
time, so nothing cared how many a layer held. After it, every caller that meets
an intersect meets it in a **loop**, and O(items) became O(intersects × items).
Measured on 1,000 spline strokes:

| 1,000 strokes, 20 intersects | v0.73.0 | v0.78.0 | after #454 |
|---|---:|---:|---:|
| `layer_influence_bound` | 0.082 ms | 1.608 ms | **0.194 ms** |
| `clay_raycast_attributed` | 1.509 ms | 3.094 ms | **1.586 ms** |

**#454 fixed the quadratic and named the residual**, which for a fixture holding
*one* intersect was the entire regression: `apply_edit` takes the bound on both
sides of every command, so a drag paid two full walks a frame either way.

**#459's suggested fix cannot work, and fails silently.** A memo keyed on
`revision` was built first. It measured 0.0348 → 0.0167 ms, exactly the 2x
predicted, and every existing test passed. `perform_edit` does not bump
`revision` — `touch_region` does, afterwards — so inside one `apply_edit` the
two calls see the *same* key and the second is answered with the first's
geometry: a bound that is too small, which is under-invalidation and shows up as
stale bricks rather than as an error. What caught it was making the memo report
its own hit count: over a 20-frame drag it read **20 walks, 0 reuses**, which is
only possible if both calls shared a key. `scene::Document::content_serial`,
advanced inside `scene::apply` — the one funnel every command-based mutation
passes through — is the key that actually separates them.

**#461 finished it.** `scene::LayerExtentCache` holds the union of every visible
item **except one**, plus that item's box folded back in. Editing the held-out
item is then one item bound and a union, whatever it did — grow, shrink, or
leave the layer's silhouette untouched — because its old box was never in the
union to begin with. An edit to anyone else re-walks holding *them* out instead,
so a drag pays one walk on its first frame and none after:

| the issue's 200-frame intersect drag | one drag frame | layer walks |
|---|---:|---:|
| subtract (control) | 0.0003 ms | 0 |
| intersect, at v0.78.0 | 0.0669 ms | 200 |
| **intersect, this release** | **0.0003 ms** | **2** |

The intersect drag now costs what the subtract control costs. **This closes
#451.**

`clay_document_extent_stats` reports the walks and the reuses, because the bound
is identical either way and nothing else can say whether the cache fired. It is
the counter that caught the first attempt, and it is in the ABI for that reason.

## Three more things the engine stopped doing (#447, #456, #460)

**A brick the refill can prove uniform is not walked** (#447). A brick whose
tape's Lipschitz bound puts the surface outside it is entirely inside or
entirely outside, and its 729 samples are one value. Measured on an M2 Max
through the C ABI:

| | 400 dabs | | 1,500 dabs | |
|---|---:|---:|---:|---:|
| cold dab | 9.22 → **5.58 ms** | 1.65x | 33.4 → **14.1 ms** | 2.37x |
| whole-model fill | 580 → **335 ms** | 1.73x | 2,213 → **1,180 ms** | 1.88x |
| warm dab, one dab later | 0.52 → **0.25 ms** | 2.1x | 0.44 → **0.17 ms** | 2.5x |
| uniform bricks proven, the model | 6,669 of 7,132 (93.5%) | | 6,584 of 6,937 (94.9%) | |

None falsely: the class counts of the whole model are identical to the walk's.
And the gate is **refused where the tape's Lipschitz bound is not a slope
bound** — `info.lipschitz` is a stepping bound, and the two coincide for most
tapes and not for all.

The same branch took the pick path off the document: `clay_raycast_attributed`
marches the cached tape at its own ray's step scale and attributes a hit without
building a document per candidate item — **0.51–0.54x of the previous cost**
across four fixtures, with the bare `clay_raycast` untouched as the control.

**A sampled volume is cropped to the brick that reads it** (#456, closes #455).
`FieldVolume::cropped(region)` is emitted in place of the whole payload whenever
the compiler is working against a cull region:

| | before | after |
|---|---:|---:|
| per-brick culled compile | 0.3166 ms | **0.0054 ms** |
| that compile's blob | 1,243,861 floats | **27,160** |
| meshing a bake, gradient normals | 1740.5 ms | **142.9 ms** |

**12.2x**, and a volume now costs 0.0208 ms a brick against the primitives'
0.0214 — indistinguishable. **The origin and the brick grid do not move**, and
that is the whole of why it is exact: the first implementation shifted the
origin to the crop's first brick and values came back differing in the last ulp,
because the kernel reads a sample through `(p - origin) / cell`. Keeping the
grid costs almost nothing — `index_` and `far_` are one float per brick *slot*
while `data_` is 729 per *stored* brick, so the samples are 99.73% of the
payload.

**A layer's matrix is built once per walk** (#460), not once per item — the
smallest of the three and the one with no interesting story.

## The extreme-poly tier, finished (#448), and a gate that counts work (#458)

`MeshSculptor` now **carries its stamp anchor** instead of rescanning for it,
and resolves to the *same* class the scan would have found by descending the
adjacency from the carried anchor to the class nearest the new centre. That
distinction is the whole design risk: `geodesic_region` accumulates path
distance **from the seed**, so using the carried anchor directly would have been
a different falloff and a different dab — and the three golden tables run on the
no-index path, so "carry the previous anchor" as the source guide writes it
would have changed every sculpt result on every platform. The bit-identity is a
gate, not a hope.

The eight remaining stamp stages are instrumented behind a null telemetry
pointer under one stage enum shared by the fixed, adaptive and hierarchy paths,
so the benchmark's `stamp*` bucket resolves; `MeshSculptor` marks its own dirty
chunks — geometry over the write region, normals when refreshed, attributes when
the verb painted — so a correct dirty stream is a property of the sculptor
rather than of each host; and the `multires + layers` benchmark rows, which were
scripted and unrun, are run and recorded.

**The BVH's affordability gate now asserts work, not time** (#458). The property
was never a duration: summarizing means the walk *stops* at a distant node and
answers with one dipole term instead of descending it, so what it saves is nodes
visited and triangles tested — integers, identical on every machine.
`mesh::BvhWalkStats` reports them through a borrowed pointer that is null by
default. The gate reads **0.863x for 16x the triangles** against a bound of
5.333, where the wall clock read 5.459; with summarizing disabled the same ratio
is **16.016x**, the triangle ratio exactly, which is how the gate proves it
catches its own regression.

**Zero cost when nobody is measuring, and that took measuring too.** Counting
both walks cost 3.8% of a `signed_distance` sweep with the pointer null;
counting only `winding_number` cost 2.3%; compiling the counters out with
`if constexpr` costs 0.4%, which is noise.

## What moves under you

Additive in ABI — **no symbol removed, no signature changed, no struct
re-laid out.** One existing descriptor grew — `clay_sculpt_policy`, by three
prefix-cache knobs appended behind the `struct_size` it already negotiates, all
three zero meaning today's behaviour exactly. One format moves, and these entry
points answer differently to a caller who changes nothing.

### The format

- **The scene and `.clayspace` formats go to minor 17.** A node's volume and
  gate are written as a document-wide payload id, with the bytes following only
  where the id is new — the rule a shared edit list has followed since minor 15,
  one level down. **A build older than 0.84.0 opening a minor-17 document FAILS
  rather than misreading it**, as it does for minors 11, 14, 15 and 16: the
  records are not length-prefixed, so the new shape desynchronises the stream and
  the reader's own bounds checks reject it. That is the safe direction and it is
  deliberate. **Writing at minor 16 restores the per-node shape exactly**, so a
  build that predates 17 opens the document and gets what it always got. What
  that downgrade loses is the deduplication and **nothing an artist authored** —
  which makes it the cheapest downgrade this format has ever had.
- The nine gallery documents were regenerated at minor 17. Their content is
  unchanged.

### The entry points

- **A `CLAY_OP_INTERSECT` edit is no longer quadratic in the layer's
  intersects**, and a drag pays one layer walk on its first frame instead of two
  per frame forever. Same bounds, same invalidation, same bricks — only sooner.
  `clay_document_extent_stats` is how you see it happen; a document with no
  intersect in any layer reports zeroes forever.
- **A per-brick evaluation drops a `move_surface` warp it cannot reach**, so a
  refill and gradient-normal meshing over a worked layer cost what the reachable
  grabs cost rather than what all of them do. Band-clamped results are
  bit-identical to the full tape *inside* the region, which is the property a
  culled tape already had and already documented. **A whole-document evaluation
  is unchanged** and still pays for every warp.
- **A deformer chain declares a larger safe step**, because the old bound
  compounded links that provably cannot act at one point. `clay_safe_step_scale`
  returns a bigger number on a layer with several grabs — 0.098 → 0.647 on
  sixteen — so a marcher takes fewer steps to the same surface. If you calibrated
  a step budget against the old figure, it is now conservative rather than wrong.
- **A refill may prove a brick uniform rather than walk it**, and
  `clay_brick_stats` counts it the same way it always counted a brick with no
  seed: refilled where the proof is made, resumed where a later dab carries it
  forward. The resume ratio reads as it did.
- **A culled tape compiles a cropped sub-volume** in place of a whole sampled
  payload. Inside the cull region the values are bit-identical; outside it a
  cropped volume answers differently, because `ctape_volume_dist` clamps a query
  onto the sampled box — the same property a culled tape already has.
- **`clay_raycast_attributed` no longer builds a document per candidate item.**
  Same hit, same attribution, about half the time. `clay_raycast` is untouched.
- **C++ embedders:** `scene::LayerExtentCache` and `scene::command_edited_item`
  are new; `item_influence_bound`, `node_influence_bound`, `node_reach_bound` and
  `node_influence_bound_in_document` take an optional trailing extent memo (the
  existing arities still compile and still recompute);
  `mesh::BvhWalkStats` is a new borrowed out-parameter on the BVH walks;
  `field::FieldVolume::cropped` is new; `MeshSculptor` carries an anchor across
  stamps and marks its own chunks.

## Fixes

- **An intersect drag cost 1.17x what it did at v0.73.0** (#451, above), and the
  first two attempts at the fix are as instructive as the third: one addressed a
  quadratic the reporter's fixture did not have, and one was silently unsound.
- **A Move grab permanently taxed every later evaluation of its layer** (#452,
  above). Not fully fixable — a warp is a domain deformation — but the marching
  collapse, which was most of it, was a bound that was wrong twice.
- **A sampled volume was compiled whole into every brick that touched it**
  (#455, above): 1.24 million floats per brick, for a brick that reads 27,160 of
  them.
- **A cold brick paid for the whole history** (#306, above), which is a hitch in
  the middle of a stroke rather than a startup cost.
- **A shared payload was written once per holder** (#453, above) — eight
  placements of one capture wrote eight copies and loaded as eight unrelated
  volumes, which also silently undid the in-memory sharing on the next save.
- **The cold refill path declined a cull index it did not need and its own
  suffix compile did** (#464, above): 3,500 µs a window, in a phase nobody had
  timed.
- **The cold-window benchmark stopped measuring a cold window on a fast
  machine**, found while running this release's checklist. The row walks a ring
  of 23 distinct brick windows so that every iteration is a first touch, and
  `--benchmark_min_time=0.2s` decides how many iterations that is: 13 on a
  GitHub Linux runner, where the row reads 16.0 ms and the gate reads 0.02x
  against a 0.25x ceiling — and **135,823 on an M-series laptop**, where the ring
  wraps 5,900 times, the row measures the warm path at 0.002 ms, and the same
  gate reads **80.84x and fails**. The three rows now fix their iteration count
  at the ring's length on every machine, and the fixture refuses the run rather
  than reporting a number if the two ever disagree.
- **The Swift smoke asserted a multires arena invariant that does not hold**
  (#446), and the smoke now runs on pull requests rather than only at release —
  a gate that only runs on the release path is one that fails on the release
  path.

## Known limits, stated rather than discovered

- **A uniform layer scale is not a similarity of a layer that blends.** Rounding
  scales with the placement and `blend.k` does not; measured at 1.289 where a
  similarity says 2. Such a placement classifies as GENERAL, promises nothing,
  and takes the old invalidation. Fixing the inconsistency would change what
  existing documents evaluate to and needs its own change.
- **A non-uniform layer scale is GENERAL** and always will be by this route: it
  changes the field's Lipschitz behaviour, exactly as a per-axis item scale
  already does.
- **The placement gesture refuses any other edit while it is open.** It holds no
  snapshot, so an edit underneath it is one it cannot reconcile. A host that
  interleaves editing with a gizmo drag must close the gesture first.
- **The prefix cache is keyed on its sampling, and a miss is silent.** A prefix
  built at one cell size and asked for at another is not an error and not a wrong
  answer — it is no acceleration, which is the one failure shape
  indistinguishable from the feature not working. That is why the three knobs
  live on `clay_sculpt_policy` beside the one `cell_size` rather than in a
  descriptor of their own, and why `clay_sdf_prefix_cache_stats` exists.
- **Composing two Move warps into one is still a research question.** The
  accumulation is bounded, reported and consolidatable; it is not removed.
- **A `.clayspace` still does not carry a multires hierarchy or an adaptive
  surface.** Unchanged from v0.78.0, and still the largest integration cost in
  the library.
- **Two automask factors still do not cross the ABI** (cavity, surface-group).
  Unchanged from v0.73.0.
- **A stroke still duplicates its alpha's samples per stamp.** Unchanged from
  v0.73.0 — and note the contrast with the stamp asset above, where the same
  problem is solved by pointer identity.
- **`voxel_remesh` sharp mode is still experimental and not manifold at
  longest-axis 96**, and **`DynamicSurface::from_mesh` still refuses a raw
  marched mesh at its default weld epsilon** (`from_mesh(weld(m))`). Unchanged.
- **The `sdf_stamp_*` device budgets still carry roughly 1.7x more headroom than
  they were drawn with**, and **`pose_region`'s device budget is still 12.7x its
  measurement**. Neither is re-derived here. Unchanged from v0.73.0.
- **`clay_list_backends` reporting metal on a real iPad has still not been
  observed by this repository.** Unchanged from v0.73.0.
- **CUDA-enabled wheels are still not shipped**, and CUDA/OpenCL/Vulkan
  arithmetic on real silicon is still a manual release-time check. Unchanged.

## Upgrading

**From v0.78.0, a rebuild is enough to link.** No symbol was removed, no
signature changed and no struct re-laid out. **What is not enough is the
format:** documents written by this build do not open in an older one.

What to check, in the order the risk falls:

1. **If you exchange `.clayspace` documents with an older build**, write at
   minor 16. A minor-17 document is *refused* by a build older than 0.84.0, not
   misread. Writing at 16 costs you the payload deduplication and nothing an
   artist authored — a file that is larger and identical in content.
2. **If a gizmo drives `clay_document_set_layer_transform`**, move it onto
   `clay_layer_placement_begin` / `_update` / `_commit`. Nothing breaks if you do
   not, but that is where sixty refills a drag become one — and
   `clay_layer_placement_report` tells you whether the placement even qualifies
   before you commit to the path.
3. **If you drive a stroke of a captured detail**, `clay_layer_place_stamps` is
   the call: one undo step, one invalidation, one shared payload. Placing stamps
   one at a time still works and costs an undo entry each.
4. **If cold bricks hitch mid-stroke**, hold a `clay_sdf_prefix_cache` and call
   `clay_brick_cache_eval_requests_seeded`. It is opt-in end to end: the default
   path is byte-identical and pays nothing.
5. **If you calibrated against `clay_safe_step_scale` on a layer with several
   Move grabs**, re-read it. The number went up and your step budget is now
   conservative.
6. **If you branch on `clay_layer_consolidate` as the only answer to an
   accumulating layer**, read `clay_layer_warp_cost` first — it says whether
   there is anything to consolidate yet.
7. **If a drag on an intersect was your slow case**, it is not any more, and
   `clay_document_extent_stats` is how you confirm the cache is firing rather
   than assuming it.

Nothing else in this release is reachable without calling something new.
