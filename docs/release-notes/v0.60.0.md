# claycore v0.60.0

Eight minor versions in one tag: 0.53.0 through 0.60.0, three days after v0.52.2.
The theme of v0.52.2 was that **a dab costs what it touches**. This one is that
**a gesture costs what it changes**: a live Smooth or Move is a transaction that
edits nothing until pointer-up, a drag re-evaluates the deformer suffix it moved
rather than the chain it sits on, a brick that was already right is resumed
rather than re-walked, and a mirrored drag is a mirrored drag rather than a drag
on both halves. Beside that, the two things the host had been asking for in
issues: **a placed node can be read back** (transform, parameters, op and blend —
and per axis, because an item can now be scaled per axis), and **a layer can be
instanced**, addressed by id, and undone as one step across every representation.

**28 merged PRs plus 2 direct commits, 87 commits, 23 OpenSpec changes. The C ABI
gained 27 entry points with nothing removed and no existing signature changed
against v0.52.2.** One struct grew — `clay_layer_info` gained `content_source` and
`share_count`, behind the `struct_size` it already negotiates. The scene and
`.clayspace` formats went from minor 13 to **minor 15**; see [What moves under
you](#what-moves-under-you) for what an older build does with a minor-15 file.

Every gate of `tools/release_check.py` passes on this tree: **1,659 unit cases
and 14,356,420 assertions**, **554 pyclay tests** (1 skipped), binding parity at
419 capabilities with 28 exempt against a **built and imported** module rather
than the source-against-source fallback, backend parity, the kernel dialect over
every profile, the license manifest, C ABI hygiene and the ctypes exercise,
`openspec validate --all --strict`, the benchmark floors, and a real
`pip install .` quickstart. The device gate ran on the reference iPad from a
clean tree at the release commit and its record is `tests/device/last-gate.json`.

win pushed it under the gate's floor.

**`sdf_consolidate` and `mask_extrude` did not move, as they did not move last
release.** Both are dominated by a serial redistance pass nothing here touched.
What changed for Smooth is that it no longer *calls* `sdf_consolidate` per dab —
that is the 219x — not that the operation got faster.

**`sdf_move` is slower than it was, and slower than it was three days ago.**

0.1391 — **1.46x**, against a committed baseline of 0.0791 ms and a budget of
0.1187 ms. **The gate does not fail it, and the reason is the one this release
spent three PRs on**: a regression must exceed the tolerance AND 0.05 ms, and
0.1214 (bracketed) against 0.0791 is 1.53x but only 0.042 ms. That is exactly the
mechanism that let #358 live through four releases, working exactly as
documented, on the same verb.

**It is not attributed and this note does not guess.** Two changes in the range
disclosed a cost on this path and either could account for part of it: #372
measured the unmirrored move path at **1.09x (`BM_MoveDrag1000`) and 1.12x
(`BM_MoveDrag10000`)** on the host for carrying a chain of grabs per warp, and
#366 widened `clay_layer_move_surface`'s reach to cover every layer sharing the
node's content. Neither was measured on device. **The baseline is deliberately
NOT re-derived** — 0.0791 ms stays as the figure a fix must return to, which is
the same decision #359 made about the last one. Filed as **#375**.

**Four cases were measured while the machine had drifted** past x1.3 of the
canary's settled value — `sdf_flatten` x1.58, `sdf_relax` x1.45, `cut_passes`
x1.44, `sdf_consolidate` x1.32 — and they sit at the end of their bundle, paying
for everything ahead of them. Their budgets hold. The run-level canary moved
**x1.88 across 149 seconds while `thermalState` read `nominal` at both ends**,
which is the case the canary exists for: the OS signal has four levels and the
device throttles inside the first.

## A live brush is a transaction (ABI 0.59.0, 0.60.0)

Two brushes had no live form at all. **Smooth bakes** — `field::relax` returns a
volume, and a host with nowhere to keep that volume between pointer events had
to bake the layer again per dab: `sdf_consolidate` plus `sdf_relax`, **313 ms +
0.73 ms per dab on the reference iPad**, so the only affordable implementation
ran once at pointer-up and the artist smoothed blind. **Move churned the
document**: written per pointer event, a drag issued one command per frame and
revved revisions, tapes, caches and picking sixty times a second to produce one
edit.

`clay_sdf_smooth_*` and `clay_sdf_move_*` are two opaque handles with the same
four verbs — `begin`, `update`, `commit`, `cancel` — plus a `destroy` that IS a
cancel, so an error path that drops the handle leaves no half a stroke behind.
**Between begin and commit the document does not change**: no nodes, no
deformers, no undo entries, and `clay_document_save_memory` taken mid-gesture
returns the bytes it returned before, which is what the ABI tests assert first.
A commit **refuses a source that moved underneath it** — the layer is
fingerprinted at begin and re-checked at commit, so an undo, a replayed journal
or another tool's edit stands rather than being overwritten by a preview computed
against a document that no longer exists.

Move's update takes the **total** displacement from the anchor, never an
increment: 0.1, 0.2, 0.5 end exactly where a single fresh 0.5 lands.
`clay_sdf_move_preview_grab_count` / `clay_sdf_move_preview_grab` report the
resolved grabs as the parameters `clay_item_add_deformer(CLAY_DEFORM_GRAB, ...)`
already takes — one without symmetry, one per reaching image with it — so a host
draws its preview through machinery it has.

Measured on a **24-thread Linux desktop** (load average 5.7 before, 7.9 after;
every gate added is a ratio between two rows of the same run, never a
millisecond floor):

| gesture | before | after | |
|---|---:|---:|---|
| Smooth, one live dab (193-item layer, cell 0.05) | 33.69 ms | **0.154 ms** | 219x |
| Smooth, whole 100-dab stroke | 3,369 ms | **53.5 ms** | 63x |
| Smooth, whole 1000-dab stroke | 33,689 ms | **211 ms** | 159x |
| Move, one live frame (1,032-item layer) | 0.0676 ms | **0.00122 ms** | 55x |
| Move, whole 1000-frame drag | 67.6 ms | **1.60 ms** | 42x |
| Move, one live frame (50,032-item layer) | 3.048 ms | **0.00122 ms** | 2,500x |

The Move frame is **flat in the model**: 0.00122, 0.00161, 0.00127 and 0.00122 ms
at 132, 1,032, 10,032 and 50,032 items, 32 items visited at every size.

**`begin()` was the cost this left on the table, and 0.60.0 takes it off.** In
0.59.0 `clay_sdf_smooth_begin` measured **33.99 ms** on the same box — within 1% of
one standalone dab, because it *was* the same whole-layer bake. In 0.60.0 `begin`
evaluates nothing: it compiles, allocates a lattice index and takes a digest, and
the working field is **materialized brick by brick under the dabs** with a halo
derived from relax's own stencil. A gesture that changed nothing now installs
nothing — no volume, no undo entry, no consolidation.

**The preview is incremental too.** `clay_sdf_smooth_preview_delta_info` /
`_delta_take` hand over exactly the bricks whose bytes are new, following
`clay_brick_cache_take_dirty`'s caller-owned-buffer convention. A short buffer
takes **nothing** and reports what it needs — taking is what clears the delta, so
a partial drain would strand bricks no later call reports. The delta accumulates
and deduplicates by brick; `generation` moves only when the preview does.
`clay_sdf_smooth_preview_item` stays as the snapshot path for a host joining
mid-gesture.

**Behind it is an editable prefix cache** (`session/sdf_prefix_cache`): the first
K roots of a layer's chain folded into an fp32 volume, with the document
untouched and every absorbed item still editable. The fold is **bit-identical**
to `compile_document` — zero difference over 20,000 random points — and three
things had to be right for that, each measured wrong first: `eval` outside stored
bricks returns a *bound*, not the distance (~14 cells off); a seed must reproduce
an *accumulator*, not a redistanced bake (0.063, two cells); and a lattice origin
is `region.min`, so a seed shares a lattice only if it shares a region (0.0074).
The cache is never serialized.

**A complexity policy, opt-in.** `clay_sculpt_policy` carries the sampling and a
budget — `min_safe_step_scale`, `max_deformer_chain`, `max_item_count`, zero
disabling each, so an all-zero policy authorises nothing — plus
`allow_consolidation`, the whole opt-in for the destructive half. It runs only
between completed strokes. What it buys, honestly, over 100 independent drags:
chain **100 → 58**, `safe_step_scale` **0.191 → 0.221**, one consolidation, and
**131 → 827 ms** of wall time. It bounds the decay; it does not remove it, and it
costs real time. That is the trade the opt-in exists to let a host decline.

## A dab resumes (ABI 0.55.0)

v0.52.2 shipped the resume seed store (#306): a brick already evaluated for the
document's prefix is seeded and only the appended suffix walked. Everything in
this section is what was built on top of it once it was in use.

**Per brick, not per batch.** The admission test was effectively "this batch's
bricks are a subset of the last batch's", so the fast path fired **only while the
brush stood still**. It is per brick now, memoizing one plan per revision. A
four-brick window sliding one brick every third dab, one appended dab per
measurement, CPU backend, dim 8 / 0.05 voxel:

| history | before | after | | worst dab before | after |
|--------:|-------:|------:|---:|-----------------:|------:|
| 1,000 | 0.31 ms | 0.03 ms | 11x | 1.04 ms | 0.12 ms |
| 5,000 | 1.10 ms | 0.05 ms | 22x | 3.90 ms | 0.39 ms |
| 20,000 | 4.60 ms | 0.15 ms | 30x | 19.50 ms | 1.36 ms |
| 50,000 | 9.75 ms | 0.52 ms | 19x | 30.41 ms | 3.65 ms |

Found in the same function: **a real correctness bug on main.** `plan_resume`
picked the last visible SDF layer and trusted the append log without checking
which layer it described; node ids are per layer and every layer numbers from 1,
so the tail check could pass by coincidence, folding the active layer's last node
on twice while the dab actually made was never evaluated — **up to 0.49 in
distance, ten cells at a 0.05 voxel, silently.** The test that covered the
scenario passed only because its fixture's ids happened not to collide.

**Off the lock.** The resumed loop no longer holds the document cache mutex
across compile and evaluate; seeds are copied out under the lock, evaluated
released, and stored back with the revision re-checked. Lock held on a 24-thread
desktop, 48 bricks at a 16-dab suffix: **65.8 → 10.0 µs** (6.6x). Against `main`
the margin narrows from 0.81 to **a wash by six concurrent refill threads**, and
the fan-out `clay.h` recommends puts every slice under the pool gate — measured
0.55–0.77x. A **`tsan` preset and per-PR CI job** came with it; the mutant that
keeps the raw seed pointer live across the unlock passes every test and only
ThreadSanitizer reports it.

**The cull index stops walking the document.** An append recomputed the layer's
cull pad with a full walk and deep-copied the cached index: at 20,000 items,
0.054 ms of walk and 0.043 ms of copy against a **0.123 ms resumed dab — 79% of
it.** `BM_CullIndexAppend` at 20k: **0.0542 → 0.000258 ms**; `BM_BrickRefillMoving20000`
**0.1233 → 0.00299 ms** (twelve-core Linux, medians of 7). Against the same append
on a document a tenth the size: **11.9x before, 1.00x after** — gated as that
ratio.

**Eviction was backwards, and the order leaked.** `touch_region` erased entries
and left their keys behind — order nodes are not counted by `entry_bytes`, so
they accumulated outside the 64 MB ceiling for as long as a session made
non-append edits. And eviction was FIFO by first insertion: the hot working set
is stored at the *first* dab and rewritten by every dab after, so under pressure
the store evicted precisely the bricks the next dab was about to ask for. It is
LRU now, one node per live seed. Honest scope: not reachable at 64 MB for a dim-8
distance-only cache (32,768 bricks), reachable for a dim-16 coloured one (~1,024).

**A seed is keyed by what it describes.** The key was the brick coordinate alone.
The band is an identity field — a tape is culled against the brick dilated by its
band, so a smaller band drops items a larger one keeps. Brick (0,0,0) seeded at a
0.15 band and asked for at 0.6: **9 of 512 samples wrong, worst error 0.105 — two
voxels — inside the band.** A wrong field, not a difference below the contract.
The key is (coordinate, dims, spacing, band) now, floats compared by their bits.

**The device-destination refill resumes.** `clay_brick_cache_eval_requests_device`
— the path a renderer uses via `clay_device_adopt` — had no resumed path at all.
It has one for backends reporting `caps().device_copy`, transferred per
contiguous run of bricks. **Vulkan implements it with a compute shader, not
`vkCmdCopyBuffer`**, because a caller's buffer need not carry transfer usage.
Measured on an **RTX 5060, driver 580, Vulkan 1.3**, 12-brick window, one appended
dab: **13.23 → 0.318 ms at 5,000 items (42x), 47.62 → 0.441 ms at 20,000 (108x)**,
with the box busier during the fast column. **Metal has no seeded path here** —
it falls back to the full walk correctly and silently, and is filed as #350
because it needs an Apple GPU to do. Multi-layer documents take the full walk on
this path by design.

**And a drag re-evaluates the suffix it moved.** A resume entry now carries a
dirty frontier and an optional prefix seed — the chain folded through the first
B roots, tagged with the structure revision it was built under. `touch_region`
keeps in-bound entries whose prefix can still serve the frontier instead of
dropping them; a structural edit retires every prefix, because ordinals are
positions and a mismatch is refusal, never remap. Warm Move-drag frame against
cold on a deep stack: **0.12–0.16x** (6–8x). Never wrong, only slower: a failed
proof falls back to the full walk.

## The move brush, three ways

**A regression, bisected and closed.** `layer_move_surface` had been ~1.4x slower
since v0.52.2 and nothing said so. Through the C ABI over a 1,000-item document,
200 samples a point with warm-up discarded: `bc0b788` 0.092 ms → after #316
**0.123** → main 0.134 → **this release 0.097**. #316 gave `apply_edit` a
region-limited invalidation costing two influence bounds and a seed-store walk
*per command*, and a Move drag issues one command per node it reaches — 257 over
that document. A gesture that can state its reach now does so **once**, in O(1)
for a drag, and states it tighter than the union of 257 whole items. On the
reference iPad `sdf_move` went **0.1160 → 0.0828 ms**, back to 1.05x its
baseline. Why it survived four releases: **no CPU benchmark covered a Move drag**,
and the one gate that saw it — the device suite — had it over the tolerance but
under the 0.05 ms noise floor. `BM_MoveDrag1000` / `10000` exist now.

**A mirrored drag was a drag on both halves.** Under a layer mirror or radial
mode the grab selected on `item_influence_bound`, which is expanded over every
emitted copy, so a ball on one side reached items on both: on the issue's
325-item fixture a grab on the ridge crest selected **22 items unmirrored and 46
mirrored, the base among them**. And the drag was not symmetric either — a +x
drag differed from its mirror image at −x on 5,536 grid samples. The drag is now
stated as the images the layer's symmetry would emit, every item tested on its
own bound against each image, one grab per reaching image ordered by value.
Result: 22 items, 244 warps against 532, per-segment refill **63.5 → 20.8 ms**
(unmirrored 14.6), and 40 random mirrored drags **bit-symmetric on an 82k-point
grid** where main was asymmetric on 38 of 40. Stated plainly: the unmirrored
path pays two allocations per reached item it did not pay before —
`BM_MoveDrag1000` **0.0881 → 0.0962 ms (1.09x)**, `BM_MoveDrag10000` 1.12x,
`BM_SdfMoveTransactionUpdate` 1.15 → 1.51 µs.

**A drag on a squashed item did nothing at all** (0.54.1). See the per-axis scale
below: the brush composed the item's frame without the innermost scale, so a grab
on a unit sphere scaled 3x on X, authored at world (3, 0, 0), landed two units
outside the sphere and moved nothing — against 0.077 on the uniform sphere. The
radius is divided by the **largest** factor, so a drag never reaches outside what
was circled.

## Read a placed node back, and scale it per axis (ABI 0.53.0, 0.54.0)

**Three readers** — `clay_layer_node_transform`, `clay_layer_node_params`,
`clay_layer_node_op_blend` — for what the host had been keeping in a side-car.
Each takes what its setter takes, so what comes out goes straight back in. A
rotation reads back as a canonical representative: angle in [0, π], and an
identity as angle 0 about **+Y** rather than about nothing, because the setter
refuses a zero axis and a reader whose output its own setter rejects is not a
round trip. The parameter count is the *current* primitive's arity in floats;
out-of-line kinds count 0. **Colour is still write-only** — deliberately, and
recorded at the call.

**An item can be scaled per axis.** A slot is a squashed capsule, an oval bolt
hole a squashed cylinder, a chamfer a box stretched on one axis — the shapes a
boolean workflow cuts with, and none was reachable from a single `float scale`.
`clay_item_set_scale_nonuniform`, `clay_layer_set_transform_nonuniform`,
`clay_layer_node_transform_nonuniform` and `clay_mesh_transform_nonuniform`;
`world = layer.xform * item.xform * diag(s)`, innermost. The engine already had
the operator (`cscale_nu_point` / `cscale_nu_dist`) and had already classified it;
the tape record already had the shape — `S⁻¹` into the inverse matrix, `min(s)`
into the scale slot, **no new opcode**.

**The cost is not the one it looks like.** Multiplying back by the smallest factor
can only shorten a distance, so the field stays 1-Lipschitz, `safe_step_scale`
does not move and nothing gets slower. What goes is `clay_tape_info`'s
`out_is_exact`: the value becomes a bound on the distance, short by at most the
ratio of the largest axis to the smallest. A uniform value, the default (1, 1, 1)
included, compiles to identical tape. A mesh has no field, so its normals go
through the inverse transpose — over 32,210 vertices of a sphere squashed 3x,
agreement with the ellipsoid gradient is **0.999999**, against 0.865830 if the
normals are merely rotated.

**A layer's scale stays uniform**, deliberately: `layer.xform * node.xform` is
consumed as a rigid frame by the move brush and the lattice gizmo, and what those
do with a per-axis frame is its own question (#373). **`brush::lattice_gizmo` has
the same squashed-frame bug the move brush had and is not fixed**: it cannot be
without widening `Deformer::cage_xform`, which is a format change and goes with
the layer arm.

## Layers: instanced, addressed, undone as one (ABI 0.56.0 – 0.58.0)

**`clay_document_instance_layer`** — the constructor the memory and dirty-bounds
contracts had described since v0.52.x without anything to create one. An edit
through one instance is an edit to the one shared list; the instance carries its
own transform, name, visibility, protection, mirror and radial. Instancing an
instance shares the same content — three layers over one edit list, not a chain.
`clay_layer_consolidate` on an instance **severs** rather than refuses, inside the
bake's own undo group. `clay_layer_info` reports `content_source` and
`share_count`.

The constructor alone would have shipped three defects, all fixed here: a
save/load round trip **multiplied the allocation** (ten instances in, ten unlinked
copies out); baking the tenth instance would have **collapsed the other nine**;
nothing could see the link after a reload. And two more found in review, both a
path answering per layer where the content is per document: an append to shared
content through the per-layer tape fast path left **every other instance stale**
(refused now), and `clay_document_move_layer`'s remove-then-add wrote the shared
list **inline into the journal**, so a crash recovery after reordering came back
unlinked — 97,950 bytes of edit list live, **195,126** replayed.

**A payload by id.** `clay_document_voxel_layer_by_id` and
`clay_document_mesh_layer_by_id`. The by-name lookups answer with the *first*
layer carrying the name and nothing enforces uniqueness, so a second layer with
the same name had an unreachable grid — and the failure was silent: the lookup
succeeded and the edit landed on the wrong layer. Resolved in the document first,
because a payload deliberately outlives its layer for redo.

**A crossing undoes as one step.** Make a voxel layer, rasterize a form into it,
undo twice, redo once: **three layers.** Two defects, and fixing either alone
leaves the bug: `add_voxel_layer` mutated the document directly rather than
through an undoable command, and **an undo group did not group** — it bundled
scene commands and only those, so a voxel, mask or mesh step between the brackets
stayed its own undo. `clay.h` had promised "bracket a burst of edits so they undo
as one step" since the bracket shipped, and for every representation but the edit
list the promise was false. A compound step now folds a closed bracket across
every representation, all-or-nothing.

**A layer's bounds, whatever it holds.** `clay_layer_bounds` reported no bounds
for a voxel or mesh layer however much material it held. It answers from the
occupied cells or the vertices now — which is what let a mesh layer drive
`clay_voxel_rasterize_mesh` for the first time through the ordinary path.

## The cull pad, twice

**A `k` a hard blend never reads padded every brick** (0.54.1). A hard profile's
smin is a step and reads no `k`, but a `k` left on a hard node — what a UI keeping
its blend slider does when the artist picks "hard" — set the layer's cull pad
anyway. On a 200-node chain alternating hard k = 0.5 with smooth k = 0.05:
**35,068 → 19,724 tape instructions over 200 bricks**, disagreements 0 → 0. The
reporter's attribution was wrong and is recorded: the 1.76x on their move brush
was **not the meshing** — on byte-identical output `mesh_bricks` is 1.24x *faster*
than v0.39.0 — it was the pad, which at their k roughly doubled survivors.

**The chain pad grows with the chain, clamped at support** (0.58.0). The pad was
`max(support, k)` per item — 4k for a quadratic profile. It is now
`min(support, k · envelope(N_eff))`, with the envelope fitted from a 700+
configuration knee campaign across three profiles, chain lengths 75–8000,
stroke/shuffled/reversed orders, radial 4–192, one to three mirror axes and both
architectures, clearing every unclamped knee by ≥ 0.5k. It counts what the tape
*folds*, not what the node map holds — a 75-node map under radial 64 is a ~4,800
contributor chain, and over the raw count the envelope was refuted at fifteen
configurations. Recovery: **−15% surviving instructions at 75 quadratic nodes,
−24% cubic**, and **never wider than main** — where the clamp binds the tapes are
instruction-identical. What it does not recover, on purpose: multi-k documents
leave up to ~4x tape on the table under any layer-wide constant; the next lever
is a per-region pad and is named in `bounds.cpp`.

## The device gate itself

The suite that produces the table above changed as much as the engine did, and
every change is a correction to what a number meant.

- **A single-timing case is scored on its median, not its worst draw.** The gallery
  cases time each stroke of a progressive sculpt once, so their axis is a sequence
  of one-shot observations, and the max of N draws is the worst draw. Over 18
  records spanning five ABI versions, `snakehook_tendrils` spread **5.94x** on the
  old statistic and **1.21x** on the median; `move_drags` read **0.149 and 0.434
  ms at the same commit**, which cost a four-merge off-device bisect. 25 budgets
  re-derived, every one tighter — `stroke_build` **24.2 → 0.51**.
- **A gallery pass repeats the half that can be repeated.** The stroke happens
  once; the evaluation after it is a pure read and is taken as the median of up
  to five. `cut_passes` went from 1.55x between runs to **1.02x**.
- **The gallery bundle is bracketed by the canary** like the measure bundle
  already was — 0 of 25 cases were, 25 of 25 are. Worth less than expected
  (~1.00x for 24 of them); the single-timing noise was the dominant cause, and an
  earlier claim to the contrary is withdrawn in the PR.
- **Every case is lifted over the gate's own noise floor.** A regression must
  exceed the tolerance *and* 0.05 ms, so a case gated only above 0.125 ms, and
  **39 of 61 measured verbs could never fail** — `trim_curve` at 0.0001 ms needed
  a **401x** regression. A timed body now performs `batch` applications and the
  record says how many; the per-application cost is `p95Ms / batch`. **Two
  optimisations switched off their own gates while this was being written**:
  #355 took `sdf_stroke_bricks` 0.164 → 0.047 ms and the per-dab quotient fell
  under the floor; `sdf_stamp_bricks` had its axis extended to 10,000 stamps to
  clear it and was back under the same day after #352. It runs to 30,000 now.
- **Three budgets could not fail** — `volume_hpolish` at 3.4 ms against a 132 ms
  budget could have got 36x slower with nothing objecting. Budgets are derived
  from a band of valid records now, not one run, and `BUDGET_SLACK` reports any
  budget over 6x its measurement. `docs/09`'s latency table is generated from
  the baseline and checked in CI; it disagreed in both directions before.
- **The coverage report says which verbs gate and which only report.** It changes
  the report and no verdict.

**Because forty cases were re-batched, their per-application figures are not
comparable to v0.52.2's** — batching amortises timer overhead and warms caches,
so a 4x drop in a batched voxel verb is the measurement changing, not the
engine. The table above quotes only cases whose batch is the same on both sides.

## What moves under you

Additive in ABI, but these entry points answer differently to a caller who
changes nothing. Each because the old answer was wrong or incomplete.

- **A minor-15 document does not open in a build before 0.58.0.** The layer record
  gained a content-source id and is not length-prefixed, so an older reader
  desynchronises and its bounds checks **refuse the file rather than misread it**.
  Written *at* minor 14 by this build, every layer's content goes out inline and
  instances open as independent copies — shapes right, sharing gone. Written at
  minor 13, a per-axis-scaled item degrades to a uniformly scaled one rather than
  a missing one. Documents are backward-open; the round trip through an old
  writer is lossy in those two ways.
- **`clay_layer_node_transform` refuses a node carrying a per-axis scale**
  (`CLAY_ERROR_INVALID_ARGUMENT`, nothing written): one float cannot express
  three. Read with `clay_layer_node_transform_nonuniform`, which answers for every
  node, uniform or not. **Both uniform setters write the whole transform and
  collapse a per-axis scale** — this ABI does not do partial updates. A host
  that never sets a per-axis scale never meets either.
- **`clay_layer_bounds` answers for voxel and mesh layers.** A caller that read
  `has_bounds == 0` as "not an SDF layer" now takes the other branch. That reading
  was never sound — an empty SDF layer reports 0 too.
- **A bracket that produced several undo steps produces one.** A host that counted
  undo steps per gesture must recount. This is the promise `clay.h` already made.
- **A saved document no longer carries voxel chunks for layers it does not
  contain, and one that already does loses them on load.** An undone creation
  keeps its grid beside the document for redo; saving that orphan let the next
  voxel layer to take the id come up holding a dead sculpt.
- **`clay_layer_node_influence_bound` and `clay_brick_cache_mark_dirty_nodes` cover
  every layer sharing the node's content**, not only the one named. Worst drift
  outside the old box: 0.119 against a 0.15 band. A host with instancing dirties
  more bricks; one without sees nothing move.
- **`clay_layer_move_surface` selects and invalidates differently.** Under a
  mirror or radial mode it reaches the items the ball reaches and their images,
  not everything either copy's bound touches; it states its reach as one box per
  image; and it re-uses seeds whose prefix survived the drag. The field is
  bit-identical to a fresh evaluation in every case tested — what changes is which
  items a drag moves under symmetry, and it now moves the ones the artist circled.
- **`SdfSmoothTransaction` commits a redistanced relax, not a relaxed redistance.**
  A brick-local field cannot start from a globally post-processed one. Both are
  sound SDFs; measured on the surface of the two-ball fixture the two commits
  differ by **0.0037 — 0.073 cells**. Four tests that asserted byte-identity
  against `relax(bake_layer(...))` were rewritten to the new contract, and the
  PR invites the argument if byte-identity should be preserved instead. ABI
  0.59.0 was never tagged, so no shipped caller saw the old one.
- **`clay_sdf_move_preview_grab` gained an index parameter** between 0.59.0 and
  0.60.0 — a signature change, allowed only because 0.59.0 was never published.
  If you built against an untagged 0.59.0 checkout, recompile.
- **Two diagnostic strings changed, no result code did**: a null transform argument
  now says `"null position"` or `"null rotation axis: name an axis and pass angle
  0 for no rotation"` instead of `"null transform"`. The issue that asked for
  this claimed the call silently succeeded; it had refused since v0.39.0, and the
  repro was run against five prebuilt libraries to say so.
- **Stored resume seeds are reseeded once after upgrading.** They were built
  under the old cull pad, so the seed gate refuses each once and takes one full
  recompile per brick per document. The gate working as designed.
- **The seed store evicts by use and keys by band.** A refill that used to
  resume a differently-banded seed takes the full walk and returns the field it
  always had to return; a store under pressure keeps the working set instead of
  evicting it first.
- **C++ embedders:** `move_brush` is now `prepare_move` composed with
  `resolve_prepared_move`; `MoveWarp` carries a chain of grabs rather than one;
  `UndoStack`'s `grouping_` is a depth, so nested brackets collapse into the
  outermost; `check_layering.py` allows `session → brush` and `session → eval`.
  `bindings/c/clay_internal.h` exists for tests, is not installed, and promises
  nothing.

## Fixes

- **The resumed dab could fold the wrong layer's node on twice** and skip the dab
  actually made — up to 0.49 in distance, silently (#343, above).
- **A resume seed keyed by coordinate alone served a wrong field across bands**
  — 9 of 512 samples, two voxels off, inside the band (#354, above).
- **A drag on a squashed item did nothing** (#330, above).
- **A crossing's undo created layers** (#356, above).
- **A saved instance came back multiplied and unlinked**, and a replayed journal
  after `move_layer` came back the same way (#366, above).
- **`clay.h` claimed nothing in the ABI removes a layer and that a stale borrow
  would fail after one.** Both halves were wrong: `clay_document_remove_layer` is
  declared ~1,900 lines above, and a removal leaves the payload beside the
  document so the borrow still resolves. The prose is corrected.
- **`rawMs` in a written baseline was the scored point, not the slowest.** Never
  fired — no gallery case was bracketed — fixed as a latent mislabel before the
  first bracketed gallery case activated it.
- **The manylinux CI job built with a bare `-j`** and two new test TUs pushed it
  past the container's memory: OOM-killed with exit 137, no compile error,
  deterministically twice at the same TU. `-j $(nproc)` now. Same class as the
  v0.52.1 tag failure.
- **MSVC `/W4 /WX` caught two things GCC did not**: a class type returned from
  inside an `extern "C"` block (C4190) and a `shared_ptr` doctest stringification
  (C2676). Both fixed; both are the reason the matrix has MSVC in it.
- **TSan under Ubuntu 24.04 aborts before a test runs** without `setarch -R`
  (`vm.mmap_rnd_bits=32`). Documented in `README.md`; the CI job does it.
- **The batched device cases jetsammed the measure bundle** on two runs of three
  until their walks were bounded to 256 positions; a 32-warp `move_drags` took
  the gallery bundle from 6.2 to 10.7 s and was reverted to one application.

## Known limits, stated rather than discovered

- **`sdf_consolidate` and `mask_extrude` are still the two slowest things in the
  suite** and this release did not touch their serial redistance pass. Smooth no
  longer *needs* consolidate per dab, which is the answer for that gesture; the
  operation itself is what it was.
- **Metal has no seeded device-refill path** (#350). It falls back to the full
  walk, correctly and silently. Needs an Apple GPU to develop against.
- **Smooth's `begin()` in 0.59.0 cost a whole-layer bake**; 0.60.0 makes it lazy,
  but the interpolation contract is now stated rather than exact: the working
  field is exact on its lattice, ordinary interpolation error between lattice
  points (7.6e-3 at a 0.03 cell), and exact outside the stored region. A
  consumer that needs the true field at arbitrary points wants the walk.
- **The complexity policy bounds the decay and does not remove it**, and costs
  wall time (131 → 827 ms over 100 drags with one consolidation). It is opt-in
  for exactly that reason.
- **The prefix cache has no C surface beyond the preview delta.** Who owns it, per
  document or per host, and how a budget is expressed are open (tasks 17.2–17.4
  of `add-sdf-prefix-cache`). Nothing is serialized, so nothing is at risk.
- **`brush::lattice_gizmo` is wrong inside a per-axis-scaled node** and is not
  fixed: it needs `Deformer::cage_xform` to carry `Transform ∘ diag`, which is a
  format change and belongs with the layer per-axis scale (#373).
- **`clay_layer_lattice_gizmo` pays the per-command bound `layer_move_surface`
  stopped paying.** Same shape, one `SetDeformersCmd` per warped node; not
  changed because no benchmark or device case covers it, and a semantic change
  to an invalidation path with no measurement is how the Move regression arrived.
- **A layer's per-axis scale** is not in this release (#373).
- **Colour is write-only** at the node reader.
- **Multi-k documents leave up to ~4x tape on the table** under the layer-wide
  chain pad; the per-region pad is the named next lever.
- **The unmirrored move path is 1.06–1.12x slower** for carrying a chain of
  grabs; a small-buffer container would remove it and was judged not worth what
  it costs the reader of `move.h`.
- **`sdf_stamp_cpu` remains outside the engine's half of a 120 Hz frame**; its
  budget is a regression ceiling, not an endorsement, and the checker reprints
  the breach on every run.
- **`sdf_move` is 1.46x its post-#361 figure on device and the noise floor
  suppresses the failure** (see the table above). Filed; not attributed; the
  baseline is left at 0.0791 ms rather than re-derived (#375).
- **Forty device cases were re-batched** and their history restarts at 0.56.0.
- **The device gate does not run in CI.** It ran on the reference iPad for this
  release; `release_check.py` refuses a tag whose engine changed since the
  recorded run, which is the only enforcement there is.
- **Five PRs in this range carry no OpenSpec change** — four are harness and
  tooling, one (#362, dirty-prefix tracking) is engine work with no spec delta.
  Flagged rather than hidden.

## Upgrading

1. **Nothing here breaks source or ABI compatibility for a C or Python caller
   built against v0.52.2.** 27 entry points added, none removed, no existing
   signature changed against 0.52.2. The one signature change in the range
   (`clay_sdf_move_preview_grab`) is against the unpublished 0.59.0.
2. **If you build against `clay_layer_info`, rebuild**: it grew two fields behind
   `struct_size`. An old caller passing the shorter size gets the fields it had.
3. **Do not open a minor-15 file with a pre-0.58.0 build** — it refuses. To hand
   a document to an older build, save at minor 14 and accept that instances
   become copies and (at 13) per-axis scales become uniform.
4. **If you read a node's transform, use `clay_layer_node_transform_nonuniform`**
   unless you know the node is uniform; the single-factor reader refuses a
   squashed node.
5. **If you count undo steps per gesture, recount**: one bracket is one step,
   across every representation.
6. **If you pin brick counts, golden meshes, or the set of items a mirrored drag
   moves, re-record them** — the new answers are the correct ones (see What moves
   under you).
7. **C++ embedders**: `move_brush` → `prepare_move` + `resolve_prepared_move`;
   `MoveWarp` carries `grabs`; `UndoStack::grouping_` is a depth.
8. **Expect one full recompile per brick per document on first use** while the
   seed store reseeds under the new cull pad.
9. `CMakeLists.txt`, `bindings/c/clay.h` and `pyproject.toml` all declare
   **0.60.0**. No tag was ever cut for 0.52.3 or 0.53.0–0.59.0; this release is
   the first published build carrying any of them.
