# claycore v0.78.0

Five minor versions in one tag: 0.74.0 through 0.78.0. The theme of v0.73.0 was
that **a brush acts where it says it acts**. This one is that **a surface is
something a tablet can hold** — and it took a whole tier to say that, because
the thing an artist wants at twenty million vertices is not a bigger mesh. It is
a representation that separates the form from the wrinkles, a stack of passes
over it that stay dialable, one way to ask what changed since the last frame,
and a vocabulary for refusing work that will not fit.

**The multiresolution hierarchy is the third representation** (0.74.0), beside
the fixed mesh and the adaptive surface, and never a mode either of them slips
into: a Catmull-Clark cage, deterministic subdivision over it, and per-level
detail stored as coefficients in a transported local frame, so `P(n) = S(n) +
F(n)·D(n)` — change the skull and the wrinkles are still there and still
attached. **The sculpt layer stack** (0.78.0) makes an artist's pass an
addressable channel on it: named, reorderable, dialable long afterwards, stored
as the same quantity a level's own detail is, because a second displacement
representation is a second thing to keep in step.

**And the memory tier is the half that makes those shippable.** One
`clay_surface_view` transport over all three representations, with four
revisions rather than one and an acknowledgement rather than an all-or-nothing
clear; a memory ledger that classifies every byte as essential, rebuildable or
undoable; a maintenance queue that refuses to run inside a stroke as a mechanism
rather than a convention; and five preflights that price an operation before it
allocates and report an overflow as a refusal — because the failure mode of a
wrapped estimate is that the operation is *allowed*.

**35 merged PRs, 192 commits on main. The C ABI gained 146 entry points with
nothing removed, no existing signature changed and no struct re-laid out against
v0.73.0** — 83 for the hierarchy and its sculpt layer stack, 14 for the
maintenance queue, 11 for the surface-view transport, 6 preflights, 5 for
memory pins, and the rest spread across the sculptors, the memory roll-up and
the three `_excluding` evaluators. Three descriptors grew, all by appending
behind the `struct_size` they already negotiate: `clay_mesh_brush_desc` gained
`stamp_azimuth` and `seed_revision`, `clay_mesh_hit` gained `seed_revision`, and
`clay_memory_report` gained nine fields for the surface tier and its roll-ups.

**Two formats do move.** The scene and `.clayspace` formats go to **minor 16**
(a layer's per-axis scale), and the brush preset format to **version 2** (the
stamp azimuth it was one field short of). Both are read below, in
[What moves under you](#what-moves-under-you), which is the section to read
before upgrading.

Every gate of `tools/release_check.py` passes on this tree: **2,294 unit cases
and 16,312,689 assertions**, none failed and none skipped; **681 pyclay tests**
(1 skipped); binding parity at **716 capabilities with 33 exempt against a built
and imported module** rather than the source-against-source fallback; backend
parity at 44 cases over every registered backend; the kernel dialect across the
CPU, CUDA and Metal profiles plus the OpenCL and Vulkan amalgamations; the
license manifest (8 dependencies, all permissive); the 15 kernel headers
byte-identical to the repository; C ABI hygiene and the ctypes exercise;
`openspec validate --all --strict`; the benchmark floors; and a real
`pip install .` quickstart in a throwaway venv.

The suite grew with the tier rather than behind it: **+369 unit cases, +82
pyclay tests and +169 binding-parity capabilities** against v0.73.0's 1,925 /
599 / 547.

The device gate ran on the reference iPad from a clean tree; its record is
`tests/device/last-gate.json`.

## On the reference iPad, v0.73.0 → v0.78.0

Measured on the **reference iPad (iPad15,5, iPadOS 26.5.2, Build 23F84)** by the
release gate: 73 cases in five cold sessions, `valid`, `thermalState` nominal at
both ends, from a clean tree at `9ed0a49a`. The record is
`tests/device/last-gate.json`.

Two comparisons, because they answer different questions. Only points whose
measurement **shape** is identical in both records are compared — same batch,
same repeats, same sample and stamp counts — because anything else is two
experiments rather than two readings of one.

| against | shape-matched points | median | over the 1.4x tolerance |
|---|---:|---:|---:|
| v0.73.0's own gate record | 298 | **0.9949x** | 1 |
| the committed baselines | 241 | **0.9932x** | 1 |

**A release that adds 146 entry points and a whole surface tier costs the
existing verbs nothing measurable.** That is the result, and it goes first
because the tier is a great deal of new machinery sitting beside paths that were
already tuned. **No baseline is re-taken here**, which is the property that makes
the second row mean anything.

### The one point over tolerance is thermal

`sdf_stroke_bricks` at 1000 stamps reads **1.428x** of v0.73.0 — 0.9074 ms →
1.2957 ms — and it is the only point in either comparison past the line. It is
the last and longest point of its case, near the end of the latency bundle, so
it pays for everything ahead of it:

| | canary drift while the case ran | p50 @1000 | p95 @1000 |
|---|---:|---:|---:|
| v0.73.0 | x1.095 | 0.8502 ms | 0.9074 ms |
| v0.78.0 | **x1.393** | 0.9927 ms | 1.2957 ms |

The 10- and 100-stamp points of the same case are flat — **1.019x and 1.016x** —

**What this run cannot settle is whether that ~1.1x residual is anything.** The

within-run figure to hold a 1.1x against. It is written down rather than
dismissed, and the honest next step is repeats on that case before the next

## A third representation (ABI 0.74.0, #405, #406)

`mesh::MultiresSurface` and `mesh::MultiresSculptor`: a base cage, a
deterministic subdivision hierarchy over it, and per-level detail as
coefficients in a transported local frame.

    P(0) = the cage    S(n) = Subdivide(P(n-1))    P(n) = S(n) + F(n)·D(n)

That is the whole point of the tier in one line. Detail is not stored as
positions, so an edit to the form beneath it does not erase it — sculpt wrinkles
at level 5, change the skull at level 1, and the wrinkles are still there and
still oriented the way they were laid down.

- **Subdivision is deterministic across platforms and runs.** Catmull-Clark with
  boundary and corner rules, and vertex/edge/face point numbering assigned in
  phases so a generated vertex's index does not depend on iteration order.
  Partial re-evaluation is bit-identical to the full one for the vertices it
  writes, which is what makes local propagation legitimate rather than a
  cheaper approximation.
- **Frames are built once at the cage and transported up** by shortest-arc
  rotation — a UV tangent where a valid parametrization exists, a deterministic
  index-chosen geometric tangent where it does not.
- **Detail is blocked sparse fp32** with dense promotion, compaction, byte
  accounting, a representation-independent checksum, and a versioned encoding
  whose decoder refuses hostile counts *before* allocating.
- **Sculpt level and display level are independent**, caches are per-level and
  droppable, and `clay_multires_drop_inactive_caches` reproduces the surface
  bit-identically when they are rebuilt.
- **Levels are added build-then-publish**, priced by `clay_multires_preflight_add_level`
  and refused over budget rather than attempted.

**It is opaque and owning, and it is not carried in a `.clayspace`.** A
`clay_multires` lives beside the document rather than inside it — the C ABI says
so in writing — and `clay_multires_serialize` hands back the bytes to store with
it. That is a deliberate ownership boundary, not an omission, and it is the one
integration cost a host takes on for this tier. The same is true of a
`clay_dynamic_sculptor`.

**Multires undo is a first-class record**, and a hierarchy carries a revision
that a host holding a live sculptor across a rebuild must compare.

## A sculpt layer stack on it (ABI 0.78.0)

An artist's pass becomes an addressable channel: named, reorderable, dialable
long afterwards. `mesh::SculptLayer` holds one `DetailField` per level, on the
same block grid, in the same transported frame — the same quantity the level's
own detail is, so there is no second displacement representation to keep in
step.

The C ABI reaches it through **39 `clay_multires_*sculpt_layer*` entry points**:
the stack's lifecycle and per-layer properties, and a layered stroke transaction
(`clay_multires_sculpt_layer_stroke_*`) with stamps, detail stamps,
frequency-aware smoothing, erase, an explicit write domain, and a cancel that
leaves the surface it found.

Two pieces of arithmetic are worth naming because both are traps, and both are
gated:

- **`merge_down` is defined by the surface it leaves, not by a concatenation.**
  The naive form solves `L' = L_l + (s_u·m_u)/(s_l·m_l)·L_u`, which is undefined
  at `s_l = 0` — a state one slider reaches. The stack stores the sum directly
  and sets the target's composition to the identity it needs, so parity holds by
  construction, at zero and everywhere else. Nothing divides by a strength.
- **A sparse mask's identity is 1, not 0.** A mask the artist has never touched
  must not erase the layer it belongs to, so an absent block means *full weight*.

**A reorder is free, and had to be made free.** Task 3.1 promises that
reordering an additive stack changes organisation and not geometry, and the case
asserting it could not fail: `move_to` invalidates no block on purpose, so the
comparison was the composed cache against itself, and two layers over a zero
base sum as a single IEEE addition, which commutes exactly. A randomised probe
over 300 five-layer stacks moved the surface in **158 of them**, worst delta
1.49e-8 — a last bit, and still a bug, because the blocks a later stroke
recomposed carried the new order while cached blocks carried the old, leaving
the surface composed two ways at once. `gather_contributors` now sums a block's
contributors **in layer-id order**; an id is minted once and a reorder never
renumbers, so composition is invariant under exactly the operation the
requirement calls free. The probe reports 0 of 300 after the fix, and the sort
costs a scan (0.87–0.90x on the deepest shape, free elsewhere).

`clay_multires_compact_sculpt_layers`, `_bake_sculpt_layer_to_base`,
`_hold_sculpt_layer_composition` and the per-layer strength, visibility, lock,
mask and detail setters complete the surface. Undo covers a layered gesture and
a layer property change alike.

## What a tablet can hold (ABI 0.78.0)

Three pieces that share one rule: **work a host may decline, priced before it
runs, reported in categories a host can act on.**

### One transport over three surfaces

A host at twenty million vertices asks three questions, and they are the same
three whichever representation it holds: what changed, give me those bytes into
a buffer I own, and what does this cost me. Answering them per representation is
three sets of entry points and three host code paths whose dirty sets mean
different things — a weld class, a face chunk and a base patch are not
interchangeable, and a host that treated them as such would upload the wrong
thing.

`clay_surface_view` is one seam over one chunk unit, built from a mesh
(`_from_mesh`), an adaptive sculptor (`_from_dynamic`) or a hierarchy level
(`_from_multires`). The shipped per-representation paths are untouched and stay
byte-compatible. What the seam adds is what they structurally cannot express:

- **Four revisions rather than one**, so an index buffer is re-uploaded only
  when connectivity changed, and a deferred normal flush is distinguishable from
  a move.
- **An acknowledgement rather than an all-or-nothing clear.** A chunk retires
  only if its revision still matches what the caller copied, so a host that
  drains half a set and drops a frame neither re-uploads everything nor loses a
  change.
- **A stale readback that says so**: the revision the caller asked for comes
  back beside what the engine is at now.

### A ledger, a queue, five preflights

- **`clay_memory_report` grows the surface tier and three roll-ups.** Six new
  category fields (`surface_content`, `multires_detail`, `sculpt_layers`,
  `surface_caches`, `surface_scratch`, `surface_undo`) and the three figures a
  memory warning actually asks for: **`essential`, `rebuildable`, `undoable`**.
  A single total is not the answer under pressure — a host does not need to know
  how big the document is, it needs to know *which part*, because that is what
  decides what it may release. The three are **derived from the category fields
  rather than stored beside them**, so a field added without being classified
  cannot make them disagree with `total`.
  The surfaces come in through a ledger the *host* fills and hands to
  `clay_document_memory_with_surfaces`, which keeps the ownership exactly where
  the ABI put it — the document gains no reference to a surface it does not own
  — and still lets one figure answer a memory warning.
- **`clay_maintenance_queue_*` holds what makes the next interaction cheaper and
  this one slower**: index rebuilds, chunk compaction, detail promotion,
  slot-pool compaction, a deferred normal flush. **It refuses to run while a
  stroke is open, and that is a mechanism rather than a convention** — "we only
  call this between strokes" is a rule that survives until the second caller.
  Nothing rebuilds on the engine's own behalf; `Bvh::quality` already records
  that a rebuild helped one of five measured deformations and hurt two, so what
  is queued is a *request*. The drain is a take/complete pair rather than a
  callback: this header has never taken a function pointer, the budget loop is
  four lines in the caller's own language, and host code that queued from inside
  a callback would mutate the vector being walked. pyclay spells the gate
  `with queue.stroke():`, the only form that cannot leave it shut when a stroke
  loop raises.
- **Five preflights, all through one capacity builder.** Mesh-to-adaptive
  conversion, the export back, a global remesh, serialization and `add_level`,
  each separating its transient peak from its result. `MultiresError` gains
  `CapacityOverflow` and `clay.h` its mirror, because the failure mode of a
  wrapped estimate is that the operation is allowed.
- **`clay_memory_pin_*`** holds a surface resident across a gesture, and
  `clay_multires_trim` / `clay_dynamic_sculptor_trim` honour a constrained
  profile at the moments a host causes rather than on a timer.

**What a trim costs the dab after it is priced rather than asserted.**
`benchmarks/bench_trim_recovery` reports **0.62–2.04x at Warning and 13–182x at
Critical**, growing with the model — which turns "prefer Warning mid-drag, or
hold a pin until the stroke ends" into advice a host can act on.

## A dispatch has a work class, and Apple a QoS to map it to (#428, #431)

The pool had one speed. On a desktop that is nearly right — the cores are
interchangeable and the scheduler has little to decide. **On a tablet it is
wrong in a way that shows up as latency and nothing else**: fast and efficiency
cores, a scheduler that reads a thread's declared intent, and a brush dab
arriving indistinguishable from a cache rebuild.

`parallel::WorkClass` is the portable vocabulary — Interactive, UserInitiated,
Utility, Background — deliberately *not* Apple's enum, because a portable core
that spells a vendor's scheduling constants into its public headers has to keep
spelling them out on every platform that lacks them. The mapping lives in one
function in one file.

The pool carries a class per job, applies it to every body that runs that job
including the issuing thread's own participation, and **restores what was
there** — the workers are persistent, so a class set and left would schedule the
next job wrong, a Utility rebuild running as Interactive because an earlier dab
landed on that worker, with nothing about the next job looking amiss.

**An unclassified dispatch is UserInitiated, so no existing call site changed.**
A work class travels down a nested dispatch rather than being written at the
leaves, which is what keeps a classification from being lost one frame deep.

## Metal answers a gradient on the device (#426, #243)

A gradient query on the Metal backend fell back to `eval_points_reference` — the
serial scalar definition of correctness and the slowest evaluator in the tree.
Measured on the deep-edit-list document: **3442 ms, against 151 ms for the CPU
backend and 13.8 ms for this backend's own distance-only path.** A host that
selected Metal for speed and asked for normals got something **23x slower than
not using the backend at all.**

Taking the four tap distances to the device makes it **3442 ms → 37.3 ms**,
which also takes it from 23x slower than the CPU to **4x faster**.

**The Vulkan backend had the same two defects** and they are fixed with it: it
refused a gradient-only query outright — the interface says a null buffer means
"not this one", and such a caller was being silently served by the CPU backend
instead — and it answered gradients with the serial walk while allocating a
scratch distance buffer to hold an answer nobody reads. It now refuses only when
nothing at all is asked for, skips the device dispatch and its two copies when
neither distance nor colour is wanted, and walks gradients with the blocked
evaluator, which is bit-identical to the reference.

## The cull gets cheaper three times (#441, #442, #319)

Culling was 99% of a dab's cost at 10,000 items and linear in item count. It is
still linear; it is a good deal cheaper per item.

- **The scan is packed and its constant clauses folded** (#441): a
  six-comparison intersection over a 24-byte record. **5.3x on `plan()` at
  50,000 items** (0.1368 → 0.0258 ms) on a document that grows in extent, 2.5x
  on one that does not.
- **A brick's reject is decided from the cached entry, not the node** (#442). A
  24-brick dab on a 50,000-item document tests 21,633 survivors per brick and
  drops about 12,000 of them; that second cull reached `Entry::node` — a pointer
  into the layer's node map, walked in chain order, so a cache miss — to ask
  `visible` and `item_influence_is_local`, when both answers were already cached
  beside it. **15.01 → 13.34 ms for that dab**, wasted-test share 21.7% → 12.1%.
- **An intersect is bounded by its layer** (#319). `item_influence_bound`
  reported `Everything` for any non-local op, and "not local" covered two things
  that behave differently. The reporter measured the same object, the same drag,
  the same scene, differing only in the operation: **19.39 ms subtracting
  against 35.52 ms intersecting** — none of it the intersect being harder to
  evaluate, all of it the difference between refilling the box the shape reaches
  and refilling the whole cache. `max(acc, item)` can only take material away,
  and only from inside what the layer already occupies. **A spatial morph is
  not** bounded that way — its radial weight saturates to exactly 1 past `r1`,
  so the result *is* the item's own field arbitrarily far from anything the
  layer occupies — and taking #319 literally would have been unsound. Those keep
  `Everything`, as do an infinite grid repeat and an unbounded primitive.

**And a surface gesture stops allocating per warp** (#375): a `MoveWarp` owns
two vectors, so materialising the whole set up front cost an allocation per
reached item, freed moments later. `apply_surface_gesture` keeps one and fills
it per item; both resolvers already `clear()` rather than reassign, so every
item after the first allocates nothing. The frontier's probe command is built
once rather than once per warp.

## Adaptive topology, completed (#427, #437, #438, #439)

The dynamic-topology change read 68/68 complete with two requirements unmet, and
the undo path had a hang in it. Both are the same shape of bug: the tests
operated on the thing being constrained, and the damage was to its neighbour or
to the storage underneath it.

- **A collapse destroyed the feature next to it.** `UvSeam` was missing from
  `collapse_blockers` — the pair-merge carries constraints from the two edges
  that weld, never from the edge that dies, so a collapsed seam edge took the
  seam with it and left no trace: on a 6-subdivision sphere, **twenty marked
  seams became zero**. And `collapse_target` asked only `is_boundary_vertex`, so
  a vertex held by a seam, a crease or a material boundary was averaged to the
  midpoint like any other — **0.137385 on a unit sphere, exactly the midpoint,
  i.e. the constraint counted for nothing**. One endpoint pinned now keeps its
  position; both pinned is refused unless the edge itself carries the shared
  constraint.
- **Undo, redo, and the next dab never returns.** After a revert and re-apply
  the *surface* is perfect — every slot, generation, liveness flag, half-edge
  link, position, colour, mask and UV identical, and `validate_dynamic_surface`
  passing on both sides. What was wrong was the pools' **free lists**: `restore`
  revives a slot in place and cannot unlink it from a singly linked list without
  a walk, and `retire` pushes unconditionally, so one replay left a list naming
  live slots, some of them twice, and — once a slot pushed twice still carried
  its old link — **cycles**. Measured after one replay: the vertex list cycled,
  202 entries visited, 201 of them live, 16 actually dead. `SlotPool::create`
  walks that list, so the symptom was a hang rather than a wrong answer.
- **The validator now sees the pool, not just the connectivity.**
  `dynamic_validate.h` opens with "every invariant a half-edge surface has,
  checkable in one call" and then checked only the connectivity — which is
  exactly the gap the hang lived in, because the surface was right. Each pool is
  now checked for the invariant the surface's own checks cannot express: the
  free list names every dead slot, once, and nothing else. It is reported
  *first*, because a wrecked list breaks no connectivity check and burying it
  would hide the one issue that explains a hang.
- **A redo restores the normals a stamp recomputed.** The undo record covered
  connectivity, positions, colours, masks and UVs, and not normals — the sync
  ran before the local recompute, no face was in the record at all, and the
  neighbours the recompute reaches were noted in neither direction. Measured on
  a two-dab gesture: **138 vertex normals and 216 face normals wrong** after a
  round trip.
- **`Adjacency::build` read past its class array** on an out-of-range index.
- **Dyntopo is now driven from Python** and stressed under contention and over a
  long session, and it has device cases on the reference iPad — baselines taken
  here, so nothing is scored against them yet.

## One brush runtime across three representations (#419)

The fixed mesh, the adaptive surface and the hierarchy shared a brush
*vocabulary* and not a brush *runtime*, and that divergence was reachable from a
shipped entry point — see [What moves under you](#what-moves-under-you) for the
automask that was silently absent on the adaptive path.

Beyond the fix, the shared runtime is what made a warm adaptive stamp cost
nothing: measured at **14 allocations before and 0 after** on a 48×48 grid with
topology disabled, with and without automask factors. The region sort's
permutation and its two sorted copies moved to a per-stamp bump arena, the ball
query's face list became a member, `write_positions` stopped building a
`std::vector<FaceId>` *per moved vertex*, and the BVH's three queries stopped
building a doubling stack each.

**A seed is now validated against the numbering it was picked in.** A
`seed_class` is an index and outlives the class space it came from: a hierarchy
rebinds its level sculptor whenever the sculpt level or the cache generation
moves, so a seed picked at one level and spent at another is still *in bounds* —
the only check there was — and names an unrelated part of the surface. The cost
is not a slightly wrong region: `geodesic_region` returns **empty** when the seed
sits farther than the radius from the brush centre, so a stale seed spends the
dab on nothing, and the host cannot tell that from a fully masked stroke.
`clay_mesh_hit` and `clay_mesh_brush_desc` carry a `seed_revision`, a stamp falls
back to the scan when it does not match, and
`clay_mesh_sculptor_stale_seeds_rejected` lets a caller prove the rejection
happened. **Zero means the caller claims nothing** and keeps every shipped caller
on the bounds check it has always had.

## Evaluate the document without one layer (#378)

`clay_eval_points_excluding`, `clay_eval_gradients_excluding` and
`clay_brick_cache_eval_requests_excluding` evaluate everything but one layer —
which is what a host drawing an isolated subtool, a ghosted layer or a
before/after comparison was previously doing by mutating the document and
putting it back.

**Neither call edits the document, and that is the other half of why they
exist.** The route a host would otherwise take — hide the layer, sample the
rest, show it again — is three edits, and an edit taken between
`clay_sdf_smooth_begin` and its commit is one the commit correctly refuses.
These are safe at any point inside a transaction and record no undo entry.

**An unknown layer is refused** with `CLAY_ERROR_NOT_FOUND` rather than read as
"exclude nothing": a host whose layer id went stale would otherwise be handed
the whole document and would draw the excluded layer twice, once from here and
once from its own preview — the exact defect these calls exist to prevent, and
one that looks like a shading artefact rather than a bug. A *hidden* layer, or
one carrying no SDF content, succeeds, because excluding it is already a no-op
and refusing would make a host branch on state it has no reason to track.

## What moves under you

Additive in ABI — **no symbol removed, no signature changed, no struct
re-laid out.** But two formats move, and these entry points answer differently
to a caller who changes nothing.

### The formats

- **The scene and `.clayspace` formats go to minor 16.** A layer record carries
  a per-axis `scale_axes` triple, appended and gated exactly as the radial
  fields above it are. **A build older than 0.78.0 opening a minor-16 document
  FAILS rather than misreading it** — the layer record is not length-prefixed,
  so the new field desynchronises the stream and the reader's own bounds checks
  reject it. That is the safe direction and it is deliberate, and it is the same
  trade minors 11, 14 and 15 already make. **Written at minor 15 by a 0.78.0
  build, a per-axis layer scale degrades to the identity triple (1, 1, 1)** —
  which is what every file written before this field meant — so the document
  opens in an older build with the layer unsquashed. Shapes are recoverable and
  the loss is visible, which is the direction the backward-open rule buys.
- **The brush preset format goes to version 2.** `stamp_azimuth` reached
  `MeshBrushSettings`, the C ABI, pyclay and Swift, and did not reach the one
  format an artist saves it in: `BrushPreset::serialize` writes an identity
  subset field by field and the subset was not revisited, **so a turned chisel
  came back unturned** — worse than an error, because it looks like it worked.
  A **version-1 record still loads** and takes the unrotated default it was in
  fact saved with; a version-2 record is refused by an older build, as it always
  was. The existing round-trip test could not have caught this: every preset in
  `reference_presets()` has an azimuth of zero, and a default round-trips to the
  default whether the schema knows the field or not.

### The entry points

- **`clay_dynamic_sculptor_stamp` honours the automask it was already being
  given.** `DynamicSculptor::gather` composed falloff, taper, gate and alpha and
  never read `brush.automask`, while the header promises "the same descriptor
  the fixed path takes" and the reader dutifully filled the four automask fields
  it then dropped. **A host already setting automask factors will now see them
  take effect** on the adaptive representation. On a sphere fixture the two
  representations now agree exactly on what a NormalAngle automask masks — 321
  vertices moved without it, 281 with it, on both. Two estimator divergences went
  with it: the adaptive automask reference and the adaptive alpha fallback took
  the nearest *face*'s normal where the fixed path takes the nearest weld class's
  angle-weighted normal. `nearest_vertex()` is now the one answer.
- **A short buffer from the surface transport is `CLAY_ERROR_BUFFER_TOO_SMALL`,
  not `CLAY_ERROR_INVALID_ARGUMENT`**, and one of the three entry points fixed —
  **`clay_dynamic_surface_dirty_chunks`** — shipped in v0.73.0 with the wrong
  code and a test asserting it. To a host the two codes mean opposite things: a
  short buffer is retryable (read the count the call just wrote, grow, ask
  again), an invalid argument says the call was malformed, so retrying it
  unchanged is a spin. A drain loop with one shared error path dropped the chunk
  and left the viewport a frame behind with nothing on screen saying so. **If you
  branch on the error code from a dirty-chunk drain, re-read it.**
- **A stale `seed_class` is rejected rather than spent**, when the caller
  supplies a `seed_revision`. Passing zero — which is what a caller compiled
  against the older descriptor does — keeps the bounds check it has always had,
  so this adds a way to be correct rather than making existing callers slower.
- **A layered stack composes in layer-id order**, so a reorder no longer moves
  the surface. If you compared composed output across a reorder and accepted a
  last-bit difference, it is now exact.
- **Compaction releases capacity, which is what it reports.**
  `DetailField::bytes` reports capacity, and `compact()`'s dense-to-sparse
  demotion rebuilt through `reset()` and a `set()` per vertex — `reset()` only
  clears, so the dense era's capacity survived and `set()` regrew it by the
  standard library's own factor. libstdc++ doubles, MSVC grows by 1.5, and on
  MSVC one compaction landed **above** the dense array it replaced (107,666
  bytes against 103,070 before). The Linux and macOS passes were allocator luck.
  A compacted field now costs exactly what a field built sparse from the start
  costs.
- **`drop_*_caches` moves the cache generation**, so a trim between two dabs is
  seen. `MultiresSculptor::bind` compares that number to decide whether the
  `Mesh&` its `MeshSculptor` holds is live, and it moved when a level cache was
  *built* and not when it was released — so a stale sculptor stayed bound to a
  freed cache. **It did not crash**: the stamp wrote into released storage, the
  level was rebuilt from the authoritative detail before reading it back, and the
  dab simply was not there, with `stamp` still returning the weld-class count it
  believed it had moved. With a memory warning after every dab — which is what an
  operating system does under pressure — **every second dab vanished silently.**
  Under ASan the same case reports heap-use-after-free.
- **An edit to a `CLAY_OP_INTERSECT` item invalidates the layer's box rather
  than the whole brick cache.** Same answer, a great deal less refilled — and
  the only thing a caller can observe is that it comes back sooner. The spatial
  morphs (`CLAY_OP_TRANSITION_LINEAR`, `CLAY_OP_TRANSITION_RADIAL`), an infinite
  grid repeat and an unbounded primitive are unchanged and still invalidate
  everything, for the reason above.
- **Metal and Vulkan gradient queries answer from the device.** Same values —
  parity holds, bit-identical to the reference on Vulkan — at a different speed,
  and a gradient-only query the Vulkan backend used to refuse is now served by
  the backend the caller selected rather than silently by the CPU.
- **C++ embedders:** `DynamicSculptor` keeps the shared `SculptWorkset` instead
  of five parallel arrays and a private slot map; `DynamicSurface::refresh_normals`,
  `one_ring` and `compute_vertex_normal` gain borrowed-buffer overloads (the
  one-argument forms remain); `resolve_move` and `resolve_magnify` return
  prepared items rather than warps; `emit_gate`'s neighbours and the six
  functions that had grown past their complexity band were split.

## Fixes

- **A collapse destroyed a UV seam or a crease on the neighbouring vertex**
  (#427, above) — twenty marked seams became zero on a 6-subdivision sphere.
- **A Dyntopo undo/redo wedged the next dab** by leaving cycles in the slot
  pools' free lists (#437, above), with the surface itself provably correct.
- **The half-edge validator could not see the storage under the surface**
  (#438, above), which is why the hang had no failing invariant.
- **A redo did not restore recomputed normals** (#439, above) — 138 vertex and
  216 face normals wrong on a two-dab gesture.
- **The adaptive sculptor dropped the automask it was handed** (above).
- **A brush preset dropped its stamp azimuth** (above), and the whole preset
  format was reachable from the wheel and ungated in it — the pyclay suite had
  no `BrushPreset` test at all. Proven by reverting the fix in full: two cases
  fail, both new.
- **A sculpt layer reorder moved the surface** in 158 of 300 randomised stacks
  (above).
- **Compaction grew a field on MSVC** (above), a portable-claim failure that
  passed on two toolchains by allocator luck.
- **A trim between two dabs left a sculptor bound to freed storage** (above).
- **`Adjacency::build` read past its class array** on an out-of-range index.
- **A layer stack chunk could declare a count it did not carry** — bounded now,
  sharing one blocking with the decoder that already refused hostile counts.
- **A chunk's size was read after a split could move the table's records.**
- **The dirty set reinstated members a merge had cleared**, and a composed field
  the stack no longer reached was leaked.
- **The multires PR shipped with eight gaps**, closed together (#407).
- **The gallery's sphere fixture was inside-out, and so was example 68's cage**
  — and the gallery had drifted **six format minors** without a gate noticing.
  CI now gates the gallery on structure, so drift stops shipping silently, and
  the nine `.clayspace` outputs are regenerated at scene minor 16.
- **The layered sculptor addressed its region by weld class rather than by work
  item**, and the ball walk left provisional slot marks on candidates the weight
  had dropped.
- **pyclay's multires sculptor defs took the wrong bound type**, and the sculpt
  layer stroke's call sites were not passing the two new brush axes.
- **`ctest --parallel 0` is a no-op**, so #432's shard split shipped running
  serially. The unit suite is sharded four ways now — **2,604 s → 1,272 s, 2.05x**
  — which is what the sanitizer jobs were waiting on.
- **The Metal interop test now skips when the paravirtual compiler refuses a
  pipeline** rather than failing a run that proved nothing.
- **A frame share was compared against a batch rather than one application**
  (`tools/check_bench.py`).
- **The preflight test allocated what it was proving would be refused.**

## Known limits, stated rather than discovered

- **A `.clayspace` does not carry a multires hierarchy or an adaptive surface.**
  Both are opaque and owning by design and live beside the document;
  `clay_multires_serialize` gives you the bytes and where they go is the host's
  decision. A host that saves only the document saves only the cage's layer, not
  the sculpt on it. This is the largest integration cost in the release.
- **The surface tier's memory figures are zero unless the host fills the
  ledger.** `clay_document_memory_with_surfaces` takes what the host collected
  with `report_surface_memory` per surface it holds. That is the ownership
  boundary being honest rather than an omission — but a host that calls the
  plain roll-up at twenty million vertices gets a number that omits the largest
  thing the artist is holding.
- **A high-detail adaptive dab does not fit a frame.** `dyntopo_stamp_fine` is
  5.625 ms per application against a 4.17 ms 120 Hz share, and the gate reports
  it on every run. That is what a detail slider costs, not a defect in the case;
  the fix is host-side. The four dyntopo cases are otherwise gated and reproduce
  their baselines to within 5% on their second measurement.
- **The device gate is five cold sessions and about eighty minutes**, up from
  four and forty, and this release's run took the full time. The dyntopo bundle is appended rather than inserted: the 69
  committed baselines were all taken in the earlier order, ordering measures at
  **2.7x against a 1.4x tolerance** on this file, and a new suite has no business
  moving them. Moving it earlier requires a full re-baseline.
- **Two automask factors still do not cross the ABI.** Cavity and surface-group
  need callbacks a descriptor cannot carry. Unchanged from v0.73.0.
- **A stroke still duplicates its alpha's samples per stamp** — roughly 800 MB
  of blob for a 200-stamp stroke carrying a 1024×1024 alpha. Filed, not fixed
  here. Unchanged from v0.73.0.
- **`voxel_remesh` sharp mode is still experimental and not manifold at
  longest-axis 96.** Unchanged from v0.73.0.
- **`DynamicSurface::from_mesh` still refuses a raw marched mesh at its default
  weld epsilon**; the round trip is `from_mesh(weld(m))`. Unchanged.
- **`sdf_stroke_bricks` cannot tell a 1.1x from noise.** It takes one
  observation per point and records no spread, which is why the thermal outlier
  above leaves a residual nobody can adjudicate. Give it repeats before reading
  anything into that case again.
- **The `sdf_stamp_*` budgets still carry roughly 1.7x more headroom than they
  were drawn with**, and **`pose_region`'s device budget is still 12.7x its
  measurement**. Neither is re-derived here. Unchanged from v0.73.0.
- **`clay_list_backends` reporting metal on a real iPad has still not been
  observed by this repository.** The Metal gradient work above was measured on
  an M2 Max, not on the tablet. Unchanged from v0.73.0.
- **CUDA-enabled wheels are still not shipped**, and CUDA/OpenCL/Vulkan
  arithmetic on real silicon is still a manual release-time check. Unchanged.

## Upgrading

**From v0.73.0, a rebuild is enough to link.** No symbol was removed, no
signature changed and no struct re-laid out, so a host compiled against 0.73.0
links against this one. **What is not enough is the format:** documents written
by this build do not open in an older one.

What to check, in the order the risk falls:

1. **If you exchange `.clayspace` documents with an older build**, write at
   minor 15. A minor-16 document is *refused* by a build older than 0.78.0, not
   misread — which is the safe direction, and still a refusal. Writing at 15
   costs you per-axis layer scale, which degrades to the identity.
2. **If you save brush presets**, version 2 is what this build writes. Version-1
   records still load. An older build refuses a version-2 record, so a shared
   preset library needs both ends upgraded — and check any preset you saved with
   a turned chisel between the azimuth landing in the ABI and this release,
   because the azimuth was dropped on the way to disk.
3. **If you set automask factors and use the adaptive sculptor**, they now take
   effect. Verify the result is what you wanted before assuming it is a
   regression: the fixed path has always behaved this way.
4. **If you branch on the error code from a dirty-chunk drain**, a short buffer
   is now `CLAY_ERROR_BUFFER_TOO_SMALL`. A retry loop that treated
   `CLAY_ERROR_INVALID_ARGUMENT` as fatal was dropping chunks.
5. **If you hold a multires surface or an adaptive sculptor**, decide where its
   bytes live. `clay_multires_serialize` is the seam and the document will not
   do it for you. Fill the memory ledger too, or your roll-up omits it.
6. **If you drive strokes stamp by stamp** — which is every interactive host —
   `clay_maintenance_queue_*` is the between-strokes seam, and
   `clay_mesh_sculptor_set_defer_normals` is what makes a per-pointer-event
   stamp affordable. Neither is required; both are the reason the tier is
   usable. **A host that defers must flush**: nothing flushes on its own,
   because the sculptor does not know where a stroke ends and guessing would
   flush mid-drag, which is the cost the switch exists to avoid. Pass the same
   `clay_mesh_deltas` the stamps were recorded into, or the deferred stroke's
   undo is not exact. (`clay_mesh_sculptor_apply_stroke`'s own `defer_normals`
   argument is unaffected and still flushes at the end of the stroke it drove,
   because there the library does know where the stroke ended.)
7. **If you pass a `seed_class` from a raycast**, pass the `seed_revision` beside
   it. Passing zero is safe and keeps the old behaviour; passing the token is
   what stops a stale seed spending a dab on nothing.

Nothing else in this release is reachable without calling something new.
