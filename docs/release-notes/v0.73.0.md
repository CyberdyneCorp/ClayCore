# claycore v0.73.0

Thirteen minor versions in one tag: 0.61.0 through 0.73.0. The theme of v0.60.0
was that **a gesture costs what it changes**. This one is that **a brush acts
where it says it acts** — and it took four separate corrections to make that
true, because four different things were being read in the wrong frame or priced
against the wrong reach: a template alpha arrived in world space and landed
nowhere, an item's gate was placed by the transform of the very item it was
meant to hold back, a chain of disjoint drags was charged as though every pair
of them compounds, and a region bake collapsed everything or nothing.

Beside that, **the mesh tier became a pipeline rather than a set of pieces**.
0.62.0 gave it an adaptive surface that refines under the brush; 0.63.0 gave it
voxel remeshing — the operation sculpting applications call DynaMesh — and
0.64.0 put that operation inside the document, with an undo record and a
revision token. 0.65.0 is the one worth reading: the round trip those three
describe **did not work at all**, because the default mesher emits zero-area
triangles and the adaptive surface correctly refuses them. `mesh::weld` is the
fix, and the note it replaces was wrong.

**19 merged PRs, 76 commits on main. The C ABI gained 52 entry points with nothing
removed, no existing signature changed and no struct re-laid out against
v0.60.0.** Two descriptors grew, both by appending behind the `struct_size` they
already negotiate: `clay_mesh_brush_desc` gained a four-field automask block and
`clay_field_report` gained `steepest_deformer_chain`, `drawable_count` and
`degradation`. **The scene and `.clayspace` formats do not move — both stay at
minor 15**, so a document written by 0.60.0 and one written by this build are
the same bytes for the same content, in both directions.

This is a release with **no format change and no ABI break, and a short list of
existing calls that answer differently** because their old answers were wrong —
a gate read in the wrong frame, a step scale charged for a compounding that
cannot happen, an advisory keyed on a symptom, and a stamp that landed nowhere.
Those are in [What moves under you](#what-moves-under-you), which is the section
to read before upgrading.

Every gate of `tools/release_check.py` passes on this tree: **1,925 unit cases
and 14,777,701 assertions**, **599 pyclay tests** (1 skipped), binding parity at
**547 capabilities with 29 exempt against a built and imported module** rather
than the source-against-source fallback, backend parity over every registered
backend, the kernel dialect across the CPU, CUDA and Metal profiles plus the
OpenCL and Vulkan amalgamations, the license manifest (8 dependencies, all
permissive), the 15 kernel headers byte-identical to the repository, C ABI
hygiene and the ctypes exercise, `openspec validate --all --strict`, the
benchmark floors, and a real `pip install .` quickstart in a throwaway venv.
The device gate ran on the reference iPad from a clean tree; its record is
`tests/device/last-gate.json`.

## On the reference iPad, v0.60.0 → v0.73.0

Measured on the **reference iPad (iPad15,5, iPadOS 26.5.2)** by the release
gate, 69 cases, `valid` with `thermalState` nominal at both ends, from a clean
tree at the release commit. Scored against the committed baselines — **none of
which is re-taken in this release** — the run is **median 1.001x over 232
shape-matched points, with nothing over the 1.4x regression tolerance.** Only
points whose measurement shape is identical in both records are compared; the
rest had their batch or repeat count changed by earlier work, and comparing
across that is comparing two experiments.

**The one result worth putting first is `pose_region`, because it changed
shape rather than size.** #386's deformer-reach fix is visible on hardware:

| stamps | baseline | v0.73.0 | |
|---:|---:|---:|---|
| 10 | 0.6272 ms | **0.2270 ms** | 2.8x |
| 100 | 0.7753 ms | **0.2277 ms** | 3.4x |
| 1000 | 1.9476 ms | **0.2266 ms** | **8.6x** |

The baseline grew with the document and this does not — 0.2270, 0.2277, 0.2266
is flat to three decimal places. That is the point of pricing a deformer chain
where its links can reach: cost stops tracking how many edits the layer holds
and starts tracking how many can actually act at a point.

Two more moved for the same family of reasons, and one against:

| case | baseline | v0.73.0 | |
|---|---:|---:|---|
| `sdf_stamp_after_drag_bricks` @100 | 0.4695 ms | **0.1817 ms** | 2.6x |
| `sdf_stamp_after_group_drag_bricks` @100 | 0.3972 ms | **0.1826 ms** | 2.2x |
| `cut_passes` @4 | 0.2808 ms | **0.2118 ms** | 1.3x |
| `sdf_stroke_bricks` @1000 | 0.8924 ms | 0.9074 ms | flat |

**`pose_region`'s budget no longer describes it, and the checker says so**:
0.231 ms against a 2.934 ms gesture ceiling is 12.7x, so that case could get
thirteen times slower without the gate objecting. It is recorded here rather
than quietly re-derived, because re-deriving a ceiling in the same change that
earned the headroom is how a budget stops being a line.

**Three cases were measured while the canary had drifted** past x1.3 of its
settled value — `sdf_flatten` x1.50, `sdf_relax` x1.40, `sdf_consolidate` x1.31
— and they sit at the end of their bundle, paying for everything ahead of them.
Their budgets hold. The run-level canary moved **x1.80 while `thermalState`
read `nominal` at both ends**, which remains the case that check exists for: the
OS signal has four levels and this device throttles well inside the first.

### The gate itself is now four cold sessions

This release could not run its own device gate, and the reason had nothing to
do with the engine. `testEveryVerbOnDevice` was killed by jetsam. It passed at
v0.60.0, and `VerbCases.swift` is byte-identical across that range — what
changed is that **seven latency cases landed ahead of it in the same process**
this cycle, and `project.yml` already recorded why that is fatal: a process
keeps its high-water mark, so each earlier test's peak becomes the next one's
floor. It died at 0 s sharing the process, and ran its full 164 s alone.

Fixing that exposed two more layers, and the sequence is worth recording
because each step looked like the whole answer:

- **Its own process was not enough.** Behind the latency bundle it died at the
  heavy tail — `mask_extrude`, `sdf_consolidate`, `sdf_relax`, `sdf_move` and
  the four authoring verbs — 21 of 31 cases in.
- **Its own session was not enough either.** It died there after 25 minutes of
  idle and again after 40, having passed twice at 30. **A gate whose result
  depends on how long the tablet rested is a coin flip, not a gate**, and each
  toss costs an hour.
- **Running it first was not free.** The latency cases are the most thermally
  sensitive suite here, and measured behind the verb bundle they came in at
  **1.34-2.16x of baselines they match to 1.024x when they start cold**. Six of
  them failed a gate with nothing wrong with the engine — which is exactly the
  2.7x ordering effect `project.yml` had already measured once.

So the peak got smaller rather than the schedule. The verb cases are split at
`mask_extrude`, where the kills actually landed, into a light bundle and a
heavy one; with the latency, parity and gallery bundles that is **four
processes in four sessions, each started cold, about forty minutes**. Cases are
matched to baselines by name, so moving one between bundles changes which
process measures it and not what it is compared against.

**No baseline is re-taken in this release**, which is the property that makes
the 1.001x median mean anything.

## The mesh tier becomes a pipeline (ABI 0.62.0 – 0.65.0)

### An adaptive surface (0.62.0)

`clay_dynamic_surface_*` and `clay_dynamic_sculptor_*` add a half-edge surface
that refines and coarsens under the brush, with **opaque handles, versioned
descriptors and a stamp report carrying three revisions** — topology, geometry
and attributes advance independently, so a host re-uploads an index buffer only
when connectivity changed and vertex data only when it moved.

Two decisions are load-bearing and both are about not lying to the host. **The
dirty-chunk transport is tested against the whole export**: a host that copies a
whole mesh per dab cannot use this at the sizes it exists for, and a chunk
stream that quietly disagrees with the surface is a host drawing something that
is not the model — plausible for a long time. The test reconstructs from every
chunk and compares the triangle multiset against the flat export. And **no
borrowed pointers into the surface**: a mutation can move or free anything, so
chunk data is copied into caller-owned buffers behind a capacity query, with
nothing allocating a heap object per chunk per frame.

The existing `clay_mesh_sculptor` is untouched, and a test says so on the same
model: a host relying on indices coming out byte-identical is unaffected by any
of this.

`examples/66_dynamic_topology.py` is the milestone — a 1,200-triangle sphere
becomes a nose, an ear and a horn, and the refinement is **local**: triangles
under the brush grow several times faster than the model's total, which is the
only thing that distinguishes local refinement from global refinement that
happens to look right from one camera. Snakehook grows 1,166 triangles as it
pulls and reaches y = 1.49 out of a unit sphere; a coarse Smooth collapses 690
of them back out, because collapse is half of what makes density follow the
brush rather than a repair bolted on beside splitting.

### Voxel remeshing (0.63.0, 0.64.0)

Every *piece* of a voxel remesher was already in this library — sample a mesh
into a field, sign a dirty mesh with a generalized winding number, march a
watertight isosurface, validate it, transfer its attributes. What was missing
was **the operation, and with it the decisions the pieces do not make**: what
resolution means, what an open surface becomes, what a request costs before it
is made, and what "the same input twice" produces.

`mesh::voxel_remesh` / `clay_mesh_voxel_remesh` is that operation. Overlapping
shells fuse, self-intersections resolve, stretched triangles disappear and the
density comes out uniform. **Vertex and polygon identity are destroyed, UVs are
dropped rather than reprojected, and detail finer than the voxel size may go
with them — all three are reported rather than left to be discovered.** Vertex
colour survives by closest-point transfer, and a caller's per-vertex mask
survives through `mesh::transfer_vertex_scalar`.

The one piece of new engineering is the sampling domain. Routing through the
dense `sample_parallel` path would be 24M BVH queries carrying a winding number
at longest-axis 256, and 1.5 billion at 1024 — right for an import and wrong for
a resolution dial. The remesh supplies its own fill, evaluating only bricks near
a triangle and signing the rest by connected region. **The samples it stores are
bit-identical to the dense path's**, which is a test rather than a claim: the
dense field is marched on the same lattice and the two meshes must agree byte
for byte.

Measured on a **24-core Linux desktop** — these are desktop figures, not tablet
figures — doubling a sphere's radius at a fixed voxel size costs **4.6x, not the
8x** a bounding-box domain would; sixteen times the source triangles at a fixed
shape and resolution costs **1.27x**.

Also here: `voxel_remesh_estimate`, cheap enough for a resolution slider at
**2.3 ms where the remesh it predicts is seconds**; a resource guard that
refuses before the field, the tree and the result are allocated and **never
silently lowers a resolution it was asked for**; an explicit open-surface policy
(Reject, Close, BestEffort), so an open source is never quietly treated as
watertight; and cancellation inside every stage.

0.64.0 puts it in the document. `clay_document_voxel_remesh_layer` captures a
mesh layer's triangles, rebuilds, validates, replaces and records — **one call,
one undo step, transactional**. A refusal, a validation failure or a cancel
leaves the layer byte-identical and adds no step; a protected layer is refused
*before* the rebuild rather than after several seconds of it.

The undo record is a new step kind holding the mesh on each side. **A vertex
delta cannot express this and must not be asked to**: a delta records no indices
— the fixed-topology contract working as intended — so one recorded against the
old geometry applied to the new is a corruption, not an undo.

A **per-layer geometry revision** moves for a wholesale replacement and never
for a sculpt. That asymmetry catches what neither older check could: a
`std::map` node's address is stable across an assignment, and a replacement
landing on the same vertex and index counts passes a count check too — so a
same-count rebuild used to leave a live sculptor stamping into an adjacency and
a BVH over triangles that no longer existed.

**One shipped guard did not survive being tested.** The hard reject on normal
incompatibility, measured on a sheet folded back through itself where a fifth of
the vertices in the clamp have a back-facing closest point, is the only variant
that makes the surface *worse*:

| projection variant | one-sided distance | self-intersecting pairs |
|---|---:|---:|
| none | 0.38643 | 0 |
| no facing test | 0.38617 | 0 |
| **hard reject (as shipped in 0.63.0)** | 0.38637 | **17** |
| **weighted (0.64.0)** | 0.38642 | **0** |

Moving a vertex fully while leaving its neighbour untouched tears. The weight
goes to zero continuously and does not, and still refuses a back-facing sheet.

### The round trip did not work (0.65.0)

**The default mesher emits zero-area triangles.** Measured on a plain analytic
sphere at a 0.02 lattice: **1,458 of 70,140 triangles — two per cent — with two
corners at bit-identical positions.** `mesh_tape` does the same; `voxel_remesh`
does it less often.

Nothing had noticed, for two reasons. Everything downstream tolerates them — an
exporter writes them, a BVH holds them, the decimator drops them itself — and
`validate` counts them as *slivers* rather than degenerates, because its
`degenerate_triangles` means repeated *indices* and these have distinct indices
at identical *positions*. So a marched mesh reports `clean()` while carrying
them.

The adaptive surface cannot tolerate them. A half-edge face with two of the same
vertex does not exist, and `from_mesh` refuses rather than silently dropping it
— the right policy, with a consequence nobody had hit: **no mesh this library
marches could become an adaptive surface at all.** 0.64.0 documented a
`to_mesh → remesh → from_mesh` round trip in three places and it did not work.
It went unfound because no caller had tried: the dynamic-topology example builds
its input analytically, so the two subsystems had never met.

**0.64.0's recorded fix was wrong, and this release says so rather than quietly
replacing it.** It recorded "pass `weld_epsilon = 0` — a marched mesh is already
welded on lattice-edge keys". Bit-identical corners are refused at *any* epsilon
including zero. It appeared to work only because the voxel remesh emits almost
none of them — its field is a sampled band rather than an analytic function, so
a crossing landing exactly on a lattice point is far rarer. **Luck, not a rule.**

`mesh::weld` / `clay_mesh_weld` is the actual fix: merge coincident vertices,
remove the triangles that collapses, compact, and report what it did. It is a
named verb rather than a repair inside the conversion, deliberately — repairing
there would fix one caller and leave the marcher emitting degenerate faces into
every other one. `from_mesh(weld(m))` reads as what it is.

Each guarantee is tested: watertightness survives (a triangle whose corners
coincide bounds nothing, so removing it cannot open a hole); **a UV seam is
preserved by default**, because duplicated positions with different UVs is how a
flat mesh *represents* a seam; every index is in range afterwards; a mesh with
nothing to merge comes back byte-identical; and the same mesh welds to the same
bytes.

Two bugs were caught in the writing. The byte-identical fast path triggered
whenever no vertices merged, so `weld` sanitised out-of-range indices only when
it happened to be doing other work — the guarantee now holds always rather than
usually. And CI caught a **SIGSEGV on MSVC and on the oldest gated AppleClang**
in the test asserting an out-of-range index is dropped rather than read: `weld`
built an adjacency before sanitizing, and `Adjacency::build` indexes with no
bounds check. Ubuntu GCC and macOS-latest passed, which is the tell — the read
was undefined and behaved undefined-ly. Malformed triangles now come out first,
and **reverting the removal makes ASan report a heap-buffer-overflow on the same
test.**

## A brush acts where it says it acts

Four fixes in this release are the same shape: something was read in the wrong
frame, or priced against the wrong reach. Each was invisible at the origin and
at the identity, which is where every fixture in the suite had put it.

### A template alpha landed nowhere (0.66.0, #392)

`brush::stamp_placement` takes a **world** surface hit and returns a **world**
frame. `stamp_deformer` fed it straight into `Deformer::alpha`, which reads
**local**. No conversion existed. The two frames coincide on an item at the
identity — which is every test in the suite and every example — so it never
showed.

Measured on a sphere at (0.4, −0.2, 0.1), rotated 0.7 rad about y, scaled 0.35,
with a 0.3-amplitude bump stamped at the world hit:

| | field moved at the click |
|---|---:|
| world placement (before) | **0.000013** |
| converted to the item's frame | **0.296** |

Both reported symptoms fall out of the mis-framing. A centre landing outside the
radius makes the region weight zero — *"a correctly placed stamp does nothing"*.
One landing inside reads a clamped border texel at every point, a constant
offset under the falloff — *"a misplaced one smears"*.

**The reported cause was not the real one, and the filed fix would have made
things worse.** The issue proposed pre-transforming the alpha in
`stamps_to_nodes`. That copies the template node by value so an alpha reaches
every stamp with its samples intact, and the deformer chain is evaluated at the
item-local point — so a template alpha authored in the template's frame arrives
in each stamp's own frame, turned by that stamp's rotation and scaled by its
radius, without the resolver touching it. That is deliberate, and it is the only
thing that makes an alpha usable through a stroke at all. Pre-transforming there
would apply the stamp transform twice and desynchronise the tape from the bound
and the Lipschitz estimate, which read the same local values. **A test locks
that convention and fails if anyone implements this the way it was filed.**

`brush::placement_in` and `stamp_deformer_in` are the fix, the latter also
dividing extent, radius and amplitude by the item's scale because they are
lengths in the same space. The frame is now stated as local at all three
authoring doors.

Also closed: a zero direction and a non-positive radius were accepted and
silently inert — the kernel substitutes local +Z for one and floors the other.
**Both are refused now**, at both doors.

### An item's gate was placed by the item it protects (0.67.0, #394)

`clay_item_set_gate` was reported as accepted and inert: a gated subtraction ate
the protected region at every threshold and width, and returned `CLAY_OK` every
time. **It is not inert. It was read in the wrong frame.**

A mask field is stored in world units on its own lattice, deliberately, and
`brush::mask_to_field` measures it there — so the volume an item carries as its
gate holds world distances at world positions. The tape then placed that volume
by `layer.xform * item.xform`, squashed by the item's per-axis scale — **moving
the protected region by the transform of the very item it was meant to hold
back.**

At the origin the two frames coincide, which is why nothing caught it: every
existing fixture, in the unit tests and in the gallery alike, gates an item with
an identity transform. A real host places its cuts, and then the protection
lands somewhere the artist never painted — which from the outside is
indistinguishable from a gate that does nothing.

**The step-scale accounting had the matching error, in the unsafe direction.**
`gate_width` is already in world units and the tape charged it against the
layer's scale. A wider gate costs less, so a layer scaled up declared a step
scale it had not earned, and a marcher stepping by it could **punch through the
masked boundary**.

None of the four places that record this frame said which frame it was, which is
how the wrong one survived; all four say it now. No format or ABI break — the
gate blob keeps its fifteen floats and the kernel reading them is untouched, so
**documents written by older versions load and now evaluate correctly.**

### A chain of disjoint drags was charged as though it compounds (0.69.0, #386)

`deformer_lipschitz` folded a chain into one running product, so every pair of
links was charged as though it compounds. **Most pairs cannot.** Grab, magnify,
pose, blob and alpha all have finite support — `clay.h` puts it as "outside the
radius the field is untouched, which is what makes it a brush rather than a
modifier" — so two whose balls are far apart have no point at which both are
anything but the identity, and their factors have nothing to multiply.

Measured: eight drags of radius 0.3 around the equator of a radius-4 sphere,
centres 3.06 apart.

| drags | step scale before | after |
|---:|---:|---:|
| 1 | 0.7059 | 0.7059 |
| 2 | 0.4983 | **0.7059** |
| 4 | 0.2483 | **0.7059** |
| 8 | 0.0616 | **0.7059** |

That is the cost of a Move-heavy session, charged for a compounding that cannot
physically happen — and nudging eight different places on a form is the normal
way a sculptor works, since a second drag on the same spot is a correction
rather than a stroke.

Each link is now priced on its own and carries the region outside which it is
the identity; links that cannot reach one another are grouped, and the bound is
the **worst group** rather than the product of all of them. A link with
unbounded support acts everywhere and is charged against every group.

**This relaxation makes the declared step scale larger, which is the one
direction in which being wrong lets a marcher step through a surface**, so the
coverage is weighted accordingly: seven cases, of which four assert that nothing
was over-relaxed. Both plausible over-relaxations — treating `pose_line` as
finite support, dropping unbounded links from the per-group fold — fail a test
that was tightened until they did.

### A region bake collapsed everything or nothing (0.73.0, #390)

Consolidation collapses a whole layer. That is the right scope for a chain that
has genuinely degraded and the wrong one for what a sculptor does, which is work
a **patch**. A host applying a region bake per gesture had two options and both
are wrong for a stroke: append a volume each time, so every later bake samples
all the earlier ones, or collapse the whole subtool and lose the parameters of
items nowhere near the stroke.

Measured on a real form, twelve gestures on one patch: **22 ms and 2 items at
the first, 93 ms and 7 at the sixth, 244 ms and 13 at the twelfth — 11x**, one
appended volume each. `clay_layer_consolidate` already took a region, but that
region is only *where to sample*: the call still collapses the entire edit list,
so a small region drops everything outside it.

**The scope is an influence closure, and that is the load-bearing decision.** It
is the same argument that made the existing scope a layer: an edit list is
ordered and its operators are relative, so "absorb the items near the stroke"
has no well-defined field of its own. What does is a region no remaining item
can reach into —

```
B = the caller's region
repeat:  S = items whose influence meets B;  B = B ∪ reach(S)
until B stops growing
```

— which terminates because B only grows and the layer's bound caps it. At the
fixed point nothing outside B moves, and inside B the bake is the whole answer
because no remaining item contributes there.

**Plain containment is not enough and the difference is not cosmetic**: absorb
only the items overlapping the region and a Subtract straddling its edge stays
behind, the material it carved comes back, and the volume cannot take it away
again. **One pass is not enough either** — an item early in the list may only be
reached after a later item widens the box, and a forward pass has already gone
past it. The test that pins this has a fixture built so a single pass takes one
item where the closure takes two, because the first version of that test passed
under both.

The closure may swallow the layer, and then this *is* a whole-layer
consolidate. That is the honest fallback rather than a failure, and the report
says so. What it buys, measured here: **six gestures on one patch leave four
items — one baked, three still parametric — where appending leaves ten.**

A missing or empty region is refused: a region merge without a region is a
whole-layer consolidate, and a host should ask for that by name.

## Pinch is a surface brush now (ABI 0.68.0, #391)

`clay_layer_move_surface` exists because a grab is per item and local: on a form
smooth-unioned from several pieces it pulls one piece's share and leaves the
rest behind. Measured on two balls at x = ±0.45 blended at k = 0.25, with a grab
of radius 0.8 and displacement 0.4 on the left item — **the left side rises
0.070 and the right 0.000.** Nothing errors. It just comes out wrong.

`CLAY_DEFORM_MAGNIFY` had the same shape and no counterpart, so Pinch could not
be a surface brush on a field at all. That left a host scaling one picked item
and calling it Pinch, rebuilding the resolver in its own code, or not offering
Pinch on SDF layers — which is what the reporting host does.

`clay_layer_magnify_surface` and its `_preview` close it, with the same contract
as move: every item the region reaches, mapped into each frame, at the front of
each chain, one undo step and one invalidation for the whole gesture, symmetry
images handled, preview pure.

**It resolves by less than a drag does, and the header says why.** A drag's
displacement is a vector, so each symmetry image reflects or rotates it; a
magnify's strength is dimensionless, and a reflection of a radial scale is a
radial scale of equal strength, so **it crosses every image untouched**. The
region to invalidate is the ball with no dilation — outside the radius the
weight is zero and the point is returned unchanged, for either sign — where a
drag's has to be dilated by the displacement.

The preparation half is **shared rather than copied**: the part that does not
depend on the gesture's magnitude is about a ball over a layer, not about
dragging. Copied, the gesture's apply half would have become a second place to
fix the two open move-brush issues.

**It is not generalised to a deform kind, deliberately.** `pose` is in the same
sentence and has the same gap, but radial pose carries an *axis* that would have
to be mapped per image, and pose along a line has no finite support — so the
reachability rule both resolvers are built on does not apply to it. A generic
`clay_layer_deform_surface` would promise something about pose that this does
not keep.

## A voxel drag is a transaction (ABI 0.71.0, #393)

**A grab of N cells is not N grabs of one cell, and the difference is not
small.** `sculpt_grab` reads the grid, resamples occupancy through the falloff
and writes back, so the next call reads its own output — and the displacement is
rounded to whole cells *after* the falloff weights it. At one cell only the very
middle of the region rounds to a cell, which inside solid material changes no
occupancy at all. **Split finely enough, the whole drag evaporates.**

Measured on a solid ball 16 cells across at cell 0.04, smooth falloff,
front-gated, the same total drag of 8 cells in +y. New cells / occupied, against
2,109 at rest:

| footprint | 1 × 8 | 2 × 4 | 4 × 2 | 8 × 1 |
|---:|---:|---:|---:|---:|
| 24 cells | 59/2157 | 61/2170 | **0/2109** | **0/2109** |
| 32 cells | 205/2200 | 169/2215 | 190/2298 | **0/2109** |
| 40 cells | 357/2205 | 376/2326 | 293/2371 | 126/2235 |

Occupancy is not conserved across the split either, so composed grabs smear and
duplicate rather than translate.

**This closed an older issue the wrong way round.** That issue was about
*sub-cell* displacements, and its advice — accumulate past the cell size
host-side, then emit — is what a host naturally implements after reading the
header. It produces exactly the stream of one-cell grabs that moves nothing.

So a drag is a transaction. `begin` captures the material as it is; every
`update` takes the **total** displacement from the anchor and resamples from
that capture. **Idempotent by construction**: a run of updates ends where a
single one to the same total would, repeating one changes nothing, and a pointer
that comes back to where it started puts the material back. On the same fixture
every split now lands on the one-emission answer.

The capture **grows with the drag** rather than being sized up front, because a
drag does not say how far it will go. That is sound only because a grab writes
inside its own footprint and nowhere else, so a cell the capture later takes in
has never been touched — stated in the header and pinned by a test, since it is
the assumption the whole mechanism rests on.

Reached from C as `clay_voxel_grab_begin` / `_update` / `_written_box` / `_live`
/ `_commit` / `_cancel` / `_destroy`, with `_destroy` cancelling an uncommitted
drag so a host that drops the handle on an error path does not find half a
gesture baked in; and from Python as `VoxelGrid.grab`, a context manager that
commits on exit and cancels on an exception.

`sculpt_grab` is unchanged, and a single update is cell-for-cell what it
produces.

## A drag previews as an ordinary document (ABI 0.72.0, #388)

`SdfMoveTransaction::preview_layer()` is what the sculpt-transaction spec names
as the way a host previews a drag — "ordinary scene content, a layer whose
affected items carry the drag, so it compiles, draws and picks like any other
layer" — and it was **C++-only**. `clay.h` carried `_preview_nodes`,
`_preview_grab_count` and `_preview_grab`, and not the content, so the route the
spec designates was closed to a C host.

What a C host did instead, per pointer event: update, write each resolved grab
onto the layer, sample the dragged surface out of the document, then **undo
every grab** inside the same segment. Two document mutations and a full undo
round-trip to draw something the transaction was already holding — and the undo
was not optional, since the commit correctly refuses a layer that moved.

`clay_sdf_move_preview_document` returns a **borrowed read-only document**: the
real document's layers with the dragged one replaced by the transaction's
preview. A layer carries its edit list by `shared_ptr`, so the copy is a vector
of handles — every untouched layer shares its content and the dragged one shares
the transaction's, which is what makes an update visible through the same handle
with nothing to keep in step.

**Two decisions worth stating.** It carries the SDF layers and not the other
representations: a voxel grid, a mask and a mesh layer are not part of the field
tape, so nothing that reads the field is affected, and copying them would charge
a drag, by value, for content it cannot change. And the preview document is
**touched on every request** — a document caches its compiled tape by a revision
the mutating entry points bump, and none of them run here, because the drag
changes the shared edit list behind the cache's back. Without the touch the
second frame of a gesture is served the first frame's tape and **the preview
freezes after one update**.

Also here, the issue's smaller ask: `clay_layer_add_deformer` had no inverse, so
undo was the only way to take a warp back — which also spends a history entry
the gesture never meant to make. `clay_layer_deformer_count`, `_remove_deformer`
and `_clear_deformers` close that. An index past the end is refused rather than
ignored, because a host that miscounted has a bug; clearing an already-empty
chain succeeds, because there is nothing wrong with that.

## The advice stops firing on the case it cannot cure (ABI 0.70.0, #387)

`clay_field_report` names the two degradation mechanisms separately, and the
engine is explicit that "a policy keyed on only one of them would miss the
other". But `advises_consolidation` was `safe_step_scale < threshold` and
nothing else — **the aggregate** — and a grab chain lowers the step scale
exactly as a stack of baked volumes does. **So the advisory fired hardest on the
case consolidation cannot help.**

Measured by the reporting host, medians over four gestures on a real form: a
bake made the polish brush **13x faster** and the move brush **6x slower**. The
move row is the striking one, because the bake *improves* the number that
triggered it — the step scale went from 0.00275 to 0.08090, a **29x win**, and
the gesture got six times slower. Nothing was in that chain to win back: the
drag had already collapsed to one grab per gesture and the layer was one
analytic item, so the bake only swapped a cheap primitive for a warped 3.3 MB
volume.

The advice now asks what a bake **wins back**, which is exactly two things: the
cost of walking an edit list, and the Lipschitz of stacked volumes, which
redistancing removes. A layer with neither is not advised. Three fields make
that decidable, appended behind `struct_size`:

- **`steepest_deformer_chain`** — the deformer mechanism's own factor.
  `longest_deformer_chain` is a *count*, so there was no number to weigh against
  `steepest_volume` and the advice had to fall back on the aggregate.
- **`drawable_count`** — of `item_count`, the nodes that are actually evaluated.
  A group is a transform and a name; keyed on `item_count`, a lone item wrapped
  in a group would have got the advice that measured 6x worse.
- **`degradation`** — naming the mechanism outright, so a host picks a cure
  rather than deriving one from a boolean.

**No new cure is claimed for the deformer mechanism.** When the mechanism is
`Deformers` the honest answer is that the layer is already parametric and cheap
per sample and it is the marching that costs — and #386 above makes that case
much rarer.

Three existing tests asserted the old advice on a one-item layer with a
nine-grab chain. They encoded the defect and are updated; the rest of what they
claim — that the bound really is that bad, and that consolidating really does
fix the bound — is untouched and still passes.

## Brush presets cross the ABI (ABI 0.61.0)

A preset crosses as **bytes on the size-query pattern**, with `struct_size` on
every descriptor and bounded fills. The automask block is appended to
`clay_mesh_brush_desc`, so a host compiled before automasking existed sends
zeroes and gets exactly the stamps it had.

**Three of the five automask factors cross.** Cavity and surface-group need
callbacks the descriptor cannot carry; their bit values are declared so the
vocabularies match, while the descriptor that carries their inputs stays a
follow-up rather than a guess made against a sample of one.

`clay_mesh_sculptor_apply_preset` is the call a host makes once it has a library
rather than a set of sliders. **The alpha is passed to it and never carried by a
preset**: image content stays caller-owned, which is what keeps a preset at 178
bytes and the whole library at 3,810 against 4,096 for one 32×32 alpha.

`examples/65_brush_presets.py` asserts what separates five presets rather than
illustrating it — and **it caught a real error in the library while being
written**: Move and Move Topological both had the surface-walk footprint, so the
one axis that is supposed to separate them did not. Move is the ball footprint
now, which is what the pair means. The rake row is the one the whole change was
for: turning the stylus 90 degrees moves **2,969 vertices differently**, and
with the orientation switched off it moves none.

## What moves under you

Additive in ABI — no symbol removed, no signature changed, no struct re-laid
out, and **the scene and `.clayspace` formats do not move (both stay at minor
15)**. But these entry points answer differently to a caller who changes
nothing. Each because the old answer was wrong.

- **A gated item evaluates where the gate was painted.** `clay_item_set_gate`
  read its mask in the item's frame; the mask is stored in world units, so the
  protected region was moved by the transform of the item it protects. **A
  document saved by an older build loads unchanged and now evaluates
  correctly** — the gate blob and the kernel reading it are untouched — so a
  host that compensated for the old placement in its own code must stop. At the
  identity nothing moves, which is why no fixture caught it.
- **`clay_layer_safe_step_scale` returns a LARGER number for a layer whose
  deformer chain is disjoint** — 0.0616 → 0.7059 on eight separated drags. A
  marcher stepping by it takes bigger steps and gets faster. It is unchanged for
  a chain whose links overlap, and for every layer with no deformers. If you
  cache this value, re-read it.
- **A gated layer's step scale is charged differently**, and the old value was
  unsafe in the punch-through direction: `gate_width` is a world length and the
  tape was dividing it by the layer's scale, so a layer scaled up declared a
  step scale it had not earned. A scaled-up gated layer now reports a **smaller**
  step scale than it did. That is the correction, not a regression.
- **`advises_consolidation` stops firing on a layer degraded only by its brush
  chain.** That is the point of the change — the bake it was advising measured
  **6x slower** on that shape. A host wanting the old meaning has
  `safe_step_scale` and its own threshold. `clay_field_report` grows three
  fields behind `struct_size`; a caller passing the older size sees none of them
  and has nothing written past the end of its struct.
- **A stamp authored with an alpha lands on the item rather than near it.** A
  host that had worked around the mis-framing by pre-transforming its alpha, or
  by authoring on an item at the identity and moving it afterwards, is now
  applying the correction twice. Measured on a placed, rotated, scaled sphere:
  the field moved 0.000013 before and 0.296 after.
- **Two stamp inputs are now refused rather than silently inert**: a zero
  direction (the kernel substituted local +Z) and a non-positive radius (the
  kernel floored it). Both return `CLAY_ERROR_INVALID_ARGUMENT` at both
  authoring doors. A host relying on either as a no-op gets an error where it
  used to get a stamp it did not ask for.
- **A voxel remesh moves a mesh layer's geometry revision; a sculpt does not.**
  A live sculptor compares that revision and now refuses a stale one — including
  the case no earlier check caught, a rebuild landing on the same vertex and
  index counts, which used to leave the sculptor stamping into an adjacency and
  a BVH over triangles that no longer existed.
- **`voxel_remesh`'s projection weights instead of rejecting.** 0.63.0's hard
  reject on normal incompatibility was the only variant that made the surface
  worse when it was finally tested — 17 self-intersecting pairs against 0 — and
  it shipped untested. A back-facing sheet is still refused; what changed is
  that the weight now goes to zero continuously rather than in a step.
- **`mesh::weld` is the fix for a marched mesh that will not become an adaptive
  surface, and 0.64.0's recorded fix for that was wrong.** `weld_epsilon = 0`
  does not help: bit-identical corners are refused at any epsilon. If you took
  that advice, replace it with `from_mesh(weld(m))`.
- **C++ embedders:** `brush::stamp_placement`'s world-frame result must go
  through `brush::placement_in` before reaching `Deformer::alpha`;
  `deformer_lipschitz` groups links by reach rather than folding one product;
  `emit_gate` writes an identity placement and no longer takes the `Layer` it
  only carried to reach the item's placement; `order_by_value` and
  `PreparedMove` are shared between the move and magnify resolvers.

## Fixes

- **A template alpha landed nowhere and the reported cause was not the real
  one** (#392, above). The filed fix would have applied the stamp transform
  twice; a test now locks the convention it would have broken.
- **An item's gate was placed by the transform of the item it protects** (#394,
  above), reported as "accepted and inert" at every threshold and width.
- **A gated layer's step scale was charged against the layer's scale**, letting
  a marcher punch through a masked boundary on a scaled-up layer (#394, above).
- **A chain of disjoint drags was priced as though every pair compounds** (#386,
  above) — 11.5x too pessimistic at eight drags.
- **The consolidation advice fired hardest on the case a bake makes worse**
  (#387, above).
- **`weld` read an out-of-range index before sanitizing it**, a heap buffer
  overflow that crashed MSVC and the oldest gated AppleClang and passed on
  Ubuntu GCC and macOS-latest. Proven by ASan; the removal now happens first.
- **`weld`'s byte-identical fast path skipped index sanitization** whenever no
  vertices merged, so the in-range guarantee held usually rather than always.
- **A same-count mesh rebuild left a live sculptor holding a stale adjacency and
  BVH** — a `std::map` node's address is stable across an assignment, so neither
  the pointer nor the count check could see it (0.64.0, above).
- **The dirty-chunk stream is checked against the whole export**, which is the
  only thing separating a working incremental upload from a host quietly drawing
  a model that is not the one it holds.
- **Move and Move Topological had the same footprint**, so the one axis meant to
  separate them did not (found by `examples/65_brush_presets.py`).
- **Two examples the gallery was silently skipping now run** (`9aa370a`).

## Known limits, stated rather than discovered

- **A stroke duplicates its alpha's samples per stamp.** The tape writes them
  once per instance with no dedup, so a 200-stamp stroke carrying a 1024×1024
  alpha writes roughly **800 MB of blob**. Found while fixing #392, filed
  separately, not fixed here.
- **Pinch is a surface brush; pose is not.** `clay_layer_pose_surface` does not
  exist, and the reason is in the header: radial pose carries an axis that would
  have to be mapped per symmetry image, and pose along a line has no finite
  support, so the reachability rule the move and magnify resolvers are built on
  does not apply to it.
- **Two automask factors do not cross the ABI.** Cavity and surface-group need
  callbacks a descriptor cannot carry. Their bit values are declared so the two
  vocabularies agree; the transport is a follow-up.
- **A voxel drag under half a cell on every axis still moves nothing.**
  Occupancy is binary and the resample is nearest-cell. What the transaction
  changes is that the total is measured from the **anchor**, so a slow drag
  accumulates toward that half cell instead of rounding to zero every frame.
- **`voxel_remesh` sharp mode is experimental and not manifold at longest-axis
  96.** Measured on a chamfered cube it is three times closer to the feature
  with a third of the triangles — and not manifold, which is exactly why it is
  marked experimental. UVs are dropped rather than reprojected, and vertex and
  polygon identity are destroyed; all three are reported.
- **`DynamicSurface::from_mesh` still refuses a raw marched mesh at its default
  weld epsilon.** `mesh::weld` is the fix and the round trip is
  `from_mesh(weld(m))`. Whether the default should change is that subsystem's
  decision and is not taken here.
- **No new cure for deformer-mechanism degradation.** #387 makes the advice stop
  lying about it; #386 makes it much rarer. Neither makes a long overlapping
  grab chain cheap.
- **The `sdf_stamp_*` budgets still carry roughly 1.7x more headroom than they
  were drawn with**, inherited from #196's workload correction and not
  re-recorded on the reference device. Until they are, treat them as a ceiling
  that will not catch what it was drawn to catch.
- **`pose_region`'s device budget is 12.7x its measurement** — 0.231 ms against
  a 2.934 ms gesture ceiling, after #386 made it 8.6x faster. The gate cannot
  object to any plausible regression in that case until the ceiling is
  re-derived, and it is not re-derived here: doing that in the same change that
  earned the headroom is how a budget stops being a line.
- **The device gate takes about forty minutes and needs a genuinely cool
  tablet.** Four bundles in four sessions, each started cold. This is not
  tuning: the verb suite sits close enough to this iPad's jetsam limit that a
  warm start is a kill rather than a slow number. `CLAY_DEVICE_COOLDOWN` sets
  the gap; setting it to 0 for a run whose numbers you intend to commit will
  produce numbers that look like results.
- **`clay_list_backends` reporting metal on a real iPad has still not been
  observed by this repository.** The build fails rather than shipping a
  CPU-only slice and the Swift smoke asserts the backend registers — both of
  which run here — but the open item from #45 is unchanged.

## Upgrading

**From v0.60.0, a rebuild is enough.** No symbol was removed, no signature
changed and no struct re-laid out, so a host compiled against 0.60.0 links
against this one. The scene and `.clayspace` formats stay at **minor 15**, so
documents move in both directions with nothing lost — this is the first release
since 0.52.x with no format movement at all.

What to check, in the order the risk falls:

1. **If you gate items** (`clay_item_set_gate`) **anywhere but the origin**, the
   protection now lands where it was painted. Remove any compensation you added
   in host code; documents already saved evaluate correctly on load.
2. **If you author stamps with an alpha**, the same applies — the stamp lands on
   the item. Remove host-side pre-transforms, and check that you never relied on
   a zero direction or a non-positive radius being a no-op, because both are now
   refused.
3. **If you cache `clay_layer_safe_step_scale`**, re-read it. It gets larger for
   disjoint brush chains and smaller for scaled-up gated layers.
4. **If you branch on `advises_consolidation`**, read `degradation` instead and
   pick the cure it names. Passing the older `struct_size` keeps the old three
   fields and is safe.
5. **If you keep a live mesh sculptor across a rebuild**, compare the layer's
   geometry revision. A same-count rebuild used to pass every check there was.
6. **If you round-trip a marched mesh into an adaptive surface**, use
   `from_mesh(weld(m))`. `weld_epsilon = 0` was 0.64.0's advice and it was
   wrong.

Nothing else in this release is reachable without calling something new.
