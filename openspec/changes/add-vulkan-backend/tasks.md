# Tasks: add-vulkan-backend

- [x] 1.1 DECIDE and record in `design.md`: the shader route — clspv over the existing OpenCL amalgamation (no new dialect, source already gated), a GLSL port, or Slang/HLSL. Decide on a real compile of the current kernel set, not on reputation. Verify clspv against the C subset the shim macros already constrain, first, because that is what makes the cheap route plausible — **clspv publishes no binaries and is not packaged; it needs an LLVM build. Chose a GLSL profile in the shim, with the four working dialects held by a token-identity gate**
- [x] 1.2 DECIDE and record: minimum Vulkan version and the extension set, chosen from what target hardware actually has. Whether `VK_KHR_shader_float16_int8` is present decides whether `fp16_storage` is claimed — **Vulkan 1.1, no optional features: cursors are indices into a storage buffer rather than device addresses. `fp16_storage` is false**

- [x] 1.4 `eval_points` and the grid evaluation that fills bricks
- [x] 1.5 Tape residency and buffer reuse from the start — this is a known cost on the Metal path and there is no reason to build it in again
- [x] 1.6 CMake preset, off by default; a machine with no Vulkan SDK configures, builds and tests exactly as today
- [x] 1.7 Shaders generated by the build from the kernel headers, never committed as generated output
- [x] 1.8 Dialect-check profile if the chosen route needs one, wired into `check_kernel_dialect.py` so a kernel change that breaks it fails per-push without a device
- [x] 1.9 Parity against the CPU reference on a REAL device, at the standard GPU tolerance, over every kernel and the composed golden scenes — **RTX 5060: the undilutable case goes 204 → 408 assertions, exactly one extra pass, all matching**
- [x] 1.10 CI job `vulkan-plumbing`, named "vulkan plumbing (lavapipe; NOT an arithmetic gate)", with the pocl precedent written into the workflow beside it. It installs glslang, so it is also the **only** runner where `check_kernel_dialect.py` stops skipping the Vulkan GLSL profile — and it fails if that profile is still skipped, since a silently-skipped gate is the pocl mistake in another form.

  It **asserts the backend registered** rather than assuming it, and that turned out to be the load-bearing step: measured locally, `parity: every registered backend` is **204 assertions with the loader left to choose and 408 with lavapipe pinned**. Without the assertion the job would pass CPU-only and prove nothing, which is precisely the failure mode the OpenCL job had. The ICD manifest is discovered rather than hardcoded (Mesa packages it as `lvp_icd.json` or `lvp_icd.<arch>.json` depending on the distribution) and a missing one is an error, not a fallback to whatever the loader picks.

## Not done

- **No CI workflow.** The lavapipe run is a documented manual step, not a job.
  Writing the workflow means deciding which runner image carries a software
  Vulkan runtime, which is a CI question rather than a backend one.
- **Gradients run on the host**, as they do on OpenCL: the tetrahedron tap is
  templated C++ in `field.h`. Recorded in the backend comment, in
  `docs/RELEASE.md` and in the delta spec rather than left to a profiler.
- **No crossover measurement**, so nothing routes work to this backend
  automatically. A caller asks for it by name.
- **`sd_stroke` and `sd_polygon2` are not compiled for Vulkan.** Neither is
  reachable from a tape (verified: no callers); both have raw-float
  counterparts that are.
