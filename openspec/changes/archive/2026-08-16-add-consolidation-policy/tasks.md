# Tasks: add-consolidation-policy

- [x] 1.1 DECIDE the trigger: **advisory, on the safe step scale, with the threshold passed per call**. `report_layer` / `clay_layer_field_report` / `Layer.field_report` measure and never bake. Automatic was rejected because a bake discards the parameters of everything it absorbs, and the two costs are paid by different people — the marcher pays for the deep chain, the artist pays for the early bake, and only one of them is in the room. Document state was rejected for the threshold because a tolerance for marching cost belongs to a viewport, a device and a frame budget rather than to the artwork; storing it would put a rendering preference in the file and need a format bump to carry it. The report names the two mechanisms SEPARATELY (`steepest_volume`, `longest_deformer_chain`) because they are genuinely different faults — hPolish degrades through a volume it resampled, Move through a deformer chain that never touches a volume — and a policy keyed on one would miss the other.
- [x] 1.2 DECIDE the scope: **a layer**. An arbitrary run of siblings has no well-defined field of its own — an edit list is ordered and its operators are relative, so a Subtract in the middle means nothing without what precedes it. A layer does: layers combine by hard union at the document level, so a layer's field is self-contained and baking one is exact with respect to the whole document. Both measured failures live inside one layer. The bake is done in the layer's LOCAL frame so its own transform still applies and consolidating moves nothing.
- [x] 1.3 Report the cost before it is paid: `ConsolidationCost` / `clay_consolidation_cost` carries bytes, brick count, sample count, sample Lipschitz, the declared Lipschitz that follows from it, the safe step scale and the bounds. `bake_layer` / `clay_layer_consolidation_cost` / `Layer.consolidation_cost` quote it without touching the document — the quote IS the bill, because it is the real bake with the result thrown away; an estimate that skipped the sampling could not report a brick count, and the brick count is where the memory is.
- [x] 1.4 Consolidate as ONE command: a `begin_group` / N × `RemoveNodeCmd` (last-first, so the replayed inverses reinsert at ascending indices) / one `AddNodeCmd` / `end_group`. No new command was needed — `RemoveNodeCmd`'s inverse already carries the removed subtree by value, so the undo record holds every absorbed item's id, parameters, colour and deformers. Routed through `apply`/`perform`, so a protected layer is refused by the vocabulary rather than by this entry point.
- [x] 1.5 State what a host may still promise: `consolidation_state` answers from the CONTENT — a layer is consolidated when its edit list is a single item carrying samples — rather than from a stored provenance flag. A mesh imported as a volume is exactly as unparametric as a bake, so a flag marking one of them would split two cases a host has to treat alike, and it would have to be serialised to survive a save. What survives is the surface at the chosen cell size; what does not is every parameter of every item absorbed and every colour but the first one's. Re-expansion is one-way and deliberately not offered: what was absorbed is in the undo record, which is where "go back" belongs.
- [x] 1.6 Both bindings, C ABI additive: `clay_layer_field_report`, `clay_layer_consolidation_cost`, `clay_layer_consolidate`, `clay_layer_consolidation_state` and three new descriptor structs, all new symbols. `Layer.field_report`, `Layer.consolidation_cost`, `Layer.consolidate`, `Layer.consolidation_state` in pyclay. Binding parity and the ABI hygiene gate both pass.
- [x] 1.7 Tests: `tests/unit/test_consolidate.cpp` (14 cases), `tests/unit/test_c_consolidate.cpp` (5 cases), 7 pyclay cases. A chain of six polish passes holds sample Lipschitz ≤ 1.10 (declared ≤ √3 × 1.10) where unconsolidated it reaches 32; a nine-drag Move stroke goes from a step scale of 0.013 to 0.577; consolidation undoes to the parametric form with ids and parameters intact and redoes as one step; a document that never consolidates serialises to identical bytes and compiles to an identical tape after reporting, quoting and state-checking.
- [x] 1.8 `examples/38_consolidation.py` added and registered in `run_all.py`. `27_move_strokes.py` and `28_hpolish.py` are UNCHANGED: they pin the degradation of the unconsolidated path, which is still exactly what it was — consolidation is opt-in and neither example calls it, so their assertions do not contradict the new behaviour and deleting them would delete the measurement the cure is judged against. `28`'s docstring pointing at "a consolidation step the engine does not yet have" is answered by 36 rather than edited away, and `docs/07-brushes-and-features.md` now carries both halves.

## Found while implementing, fixed here

- [x] `FieldVolume::sample` never measured what it stored, so every bake declared its result 1-Lipschitz whatever it had just written — `from_document` of a two-pass polish chain declared 1.0 for samples varying at 14× the cell size, licensing exactly the overstep the declared bound exists to prevent. It now measures, like every other volume producer already did. Regression test: `test_consolidate.cpp`, "a sampled volume never declares a bound smaller than its samples measure". One existing assertion in `test_pyclay.py` and one in `examples/29_claybuildup_smooth.py` were pinning the bug (`relaxed(...).sample_lipschitz <= 1.05` against a relief field that genuinely measures 6.19); both now compare relax's output against its SOURCE, which is what their own comments always claimed.
- [x] Baking does not bound the Lipschitz, which the proposal assumed it did. `field::redistance` (fast sweeping, unsigned solve with the input's sign put back) is the new primitive that does, and `FieldVolume::compact` is what stops a repeatedly consolidated chain growing a brick of stored shell per bake.

- [x] 0.1 SEQUENCING (see ROADMAP, "What can run in parallel"): no `.clayspace` bump — volumes already serialise; never touches VoxelGrid, so it runs in parallel
